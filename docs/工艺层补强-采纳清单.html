链接进给刀具

来源：docs/rust-cnc-cam-research.md（25 章调研，2026-11-07） 本文只写取舍与落点，不重复调研内容。判据：能不能解掉我们挂着的具体问题。

写于 2026-11-07 · 当前基线：叶轮 1 解析口径 98.0% / 残料 0.4% / 过切 1.6%

0. 一句话判断

调研文档的算法层可以当规格用；但它对"仿真精度"只给了"加体素"一条路（0.05 mm 要 550 MB~2.7 GB）， 而我们的解析口径（点到扫掠体并集的有符号距离）是第三条更便宜的路——这条要守住，不要被文档带跑。

真正补短板的是工艺层：链接安全、进给调度、刀具形状。这三块我们目前是空白。

1. 直接采纳（按优先级）

1.1 链间抬刀自适应 ✅ 已完成（§52）

实测：叶轮 1 空移 66.0 → 19.1 m（−71%）、擦料 9 → 1；桌腿件 4.8 → 1.7 m； 平均抬刀 4.4 / 4.0 mm（固定 18 mm 证明过保守）。合格率一位不变。 未做：三段折线（现在是沿刀轴退）、擦料时的分级兜底。

原始方案（两级安全高度 + 三段折线）⭐ 最急

我们的问题：link_ok 只计数擦料（叶轮 1 现在 8~12 处），不解决。 每条链收尾 G0 抬到 18 mm（刃长+2）再横移，空移 66 m 里 50 m 是这个。

文档给的方案（§5.11.2）：

link(A,B):  skim  = 沿途毛坯/零件局部包络 z-max + 余量
            clear = 全局安全面
  for z in [skim, clear]:              # 先低后高，失败升级
      path = 竖(A→z) - 平(A→B @z) - 竖(→B)
      if sweep_clear(path): return path
  兜底：垂直退到 clear + 平移；仍碰 → 报错，不静默

落点：crates/cam/src/surface.rs

  • 新增 skim_z(a, b) -> f64：沿 A→B 采样 ix.min_dist，取"能过的最小高度"
  • link_ok 从"计数"改成"选择"：order_runs 里已按距离取前三名，改成 按 (是否安全, 抬刀高度) 排序
  • 安全高度从 g.flute + 2.0 改成 min(skim + 余量, clear)

验收：叶轮 1 的"链间擦料"归零或 ≤2，空移从 66 m 降到 50 m 以下，合格率不降。

为什么优先：这是唯一一条"已挂三轮、有量化指标、文档给了伪代码"的项。

1.2 进给自适应（恒 MRR，v1）

我们的问题：全程 F800，内角/全宽切削处负载骤增——这是我们度量里完全看不见的维度 （±0.15 合格率只看几何，不看让刀/振纹）。

文档给的方案（§5.11.1）：

vf(i) = clamp(vf_ref · (ae_ref·ap_ref) / (ae(i)·ap(i)), vf_min, vf_nom)

三遍：①逐点限载 → ②滑窗前后包络（必须向前看：进拐角前先降）→ ③斜率限幅（|ΔF| ≤ 20%）。

落点：

  • Process 加 feed_adaptive: bool + ae_ref / ap_ref / vf_min
  • 啮合查询复用现成的 MeshIndex：ae(i) ≈ 刀心到材料表面的距离（我们已有 min_dist）
  • G 代码输出：段→F 映射，等值合并省 F 字（F 是模态）

验收：内角处 F 自动降到 0.4~0.6×名义值；总时长变化 <±15%；几何指标一位不变（F 不影响切除量）。

注意：文档说开源界只有局部拐角降速，逐点啮合调制是空白——但这条是"工艺质量"， 我们的仿真看不见它的好处（没有力学模型），只能验证"F 变了、几何没变"。别声称"提高了表面质量"。

1.3 可侧铣度检测器（不做刀路，只做判定）

我们的问题：叶轮试过 --rotary（回转吻合度 0%）、定轴（可达面 15.4%），结论是 "侧刃铣要直纹面，对非直纹叶片无解"——但没有量化"这片能不能侧铣"。

文档给的判据（§5.11.4，Crane/Stein/Grinspun 2018 双条件）：

  • 角亏 K_i = (2π − Σθ_j)/A_i（我们已有 cotan，可直接算）
  • 零主曲率：|κmin| < εκ 且各向异性 → κmin 特征向量 = 候选母线
  • 逐母线 PCA 残差 max ≤ 0.02~0.05、RMS ≤ 0.01；扭转 ≤ 2~4°

落点：crates/cam/src/surface.rs 或新 developable.rs

fn swarf_candidates(mesh) -> Vec<Band { 母线族, 残差, 扭转角, 角亏, 结论 }>

验收：对叶轮输出"可侧铣条带 0 条（原因：扭转 47°/角亏 0.3）"这种可解释的拒绝； 对手工做的直纹测试件输出"可侧铣"。

价值：把"做不了"变成"能证明为什么做不了"，这是文档里唯一一条我们缺的判定能力。

1.4 桶形刀（3+2 原型）

我们的问题：点铣的切长 16 m / 空移 66 m，本质是球头行距受限（√(8R·tol)）。

文档给的公式（§21.4）：同残留下行距增益 = √(R_b / R_球)，实测 7.9~10.8×。

落点：crates/tool/src/lib.rs

  • Profile 加"环面片段"（大半径 R_b 的圆弧母线，弧段端点）
  • 3+2 定轴下复用圆鼻刀"滚圆"逻辑：滚圆半径换成 R_b，加弧段边界检查
  • 行距按有效半径而非刀径

验收：同一残高下，桶刀的行距是球头的 √(R_b/R_球) 倍（比如 4~8×）， 总切长同比下降；几何指标不退化。

风险：文档明确说"3 轴小曲率件收益为负"，只在大曲率半径 + 五轴可达时有意义。 我们只有叶轮一个考题，可能测不出收益——优先级低于 1.1/1.2。

2. 参考但改造

2.1 三轴走刀方向：区域投票，不是逐点场

我们 11-07 做的逐点流向场失败（§50：链 −3% 但切长 +2%、块 +311）。 文档 §5.11.3 给的是整区一个方向的加权投票：

信号 权重
主曲率（P10 分位数，比均值稳） 0.5
陡壁（罚跨梯度，鼓励等高线） 0.25
区域长轴（少抬刀） 0.15
顺逆铣（打破并列） 0.05~0.1
根切点方向硬禁用 硬约束

为什么它可能比我们的强：文档明确写"κn 在主方向附近是二阶驻点，偏 10~15° 行距损失仅 3~8%" ——不需要逐点精确，而我们的逐点结构张量恰恰在叶片上噪声大。

落点：surface.rs 里把 flow_field 降级为"每点给一个候选方向"，加一层全局投票决定单一方向； --flow vote 打开。预期拿回 3~8% 行距。

2.2 体素分辨率定标：采纳"显式化"，不采纳"上 0.05 mm"

文档 §8.9 的表格（0.05 mm = 550 MB / 30~90 s；0.02 mm 不可行）可以用来做启动前预算提示： 按包围盒 + 表面积预估内存/耗时，超阈值自动降档并打印。这条成本极低，值得做。

但不要因为文档说 0.05 mm 才是验证档就去降 h——我们的验收口径是解析的（§39/§47.1）， h 只影响体积积分和可视化。这一条要在 AGENTS 里写明，避免以后被文档带跑。

3. 不采纳（含理由）

文档条目 理由
§8.10 真自适应 ADF（单树内体素尺寸随节点变） 文档自己说"研究级、跨分辨率拓扑缝合难、确定性难保"——与"逐位可复现"铁律直接冲突
§8.9 全局 0.05 mm 体素 550 MB~2.7 GB / 30~90 s，迭代节奏扛不住；解析口径已绕过
§5.11.4 侧刃 swarf 刀路 只做检测器（1.3）；生成要直纹面拟合 + DP 母线搜索，对非直纹叶轮无解
§5.11.1 颤振 / SLD 稳定叶瓣 要实测频响函数，我们没有；用全局安全系数 0.8 兜底即可
§5.12 样条后置 控制器兼容性差；JD 同几何的圆弧内插够用
§19.4 国内竞品价格 文档自己标了"未验证"

4. 我们比文档强的地方（守住，别被改掉）

  1. 解析验收口径：sweep_deviation（设计面点到刀具扫掠体并集的有符号距离，与 h 无关） + attribute_points（逐点归因到刀号/行号）。文档的验证体系只有体素/dexel 一条腿； 我们在 h=0.6 下拿到了与 h 无关的读数，并有"体素报的过切 79% 是亚体素薄壁"的实证（§39）。
  2. 刀柄分四段查碰撞（§49/§51）：刃豁免 / 等径颈 / 缩颈 / Ø6 柄。 文档 §8.7 只写"保守推进 + GJK"，没有这条分段语义。
  3. 多线程确定性：并行只按块号摊平，CNCSIM_THREADS 可对拍。文档没有涉及。

5. 建议顺序

1.1 链接安全   → 解掉"链间擦料 8~12"，空移 −20%
1.2 进给自适应 → 全新维度（几何指标不变，工艺参数合理）
2.1 方向投票   → 把 §50 的负结果换成区域级方案
1.3 侧铣判定   → 给出可解释的"做不了"
1.4 桶刀       → 需要大曲率件才有考题

前两项做完再谈后面；1.4 建议等有第二个合适工件再启动。
