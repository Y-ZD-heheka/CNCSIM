计算精度：float 够不够

日期：2026-10-28 结论：分三档用，不是一刀切。而且真正的精度瓶颈不是 float 宽度。 连带修正 ADR-004 §2.5 的检出下限

0. 结论

四句话：

  1. f32 在 1000 mm 量级的绝对精度约 0.06 µm——对加工（公差 10 µm）绰绰有余。
  2. 但精度瓶颈不在 float，在 SDF 的 i8 量化：3.15 µm/档。换 f64 一点用没有。
  3. 推荐三档：标量路径 f64（免费）、SIMD 热路径 f32（快 2×）、体素索引用整数（本来就精确）。
  4. 想真正提高精度，该花在 i16 上，不是 f64 上——内存翻倍换 65 倍精度。

顺带修正一个错误：ADR-004 说碰撞检出下限 0.17 µm，那是采样密度的限制。实际被 i8 量化卡在 1.6 µm。采样密度那 0.17 µm 根本达不到。

1. f32 绝对精度速查

量级 典型场景 f32 ULP f64 ULP
1 mm 刀具半径细节 0.12 nm 0.2 fm
30 mm 刀柄半径 1.9 nm 3.6 fm
200 mm 毛坯尺寸 0.015 µm 28 fm
1000 mm 机床行程 0.061 µm 0.11 pm
2000 mm 大龙门 0.12 µm 0.23 pm
7200 s 2 小时程序时间 0.49 ms 0.9 ps

两个值得注意的点：

  • 1000 mm 处 f32 的 ULP 是 0.061 µm——比加工公差小 160 倍，位置精度完全够。
  • 时间到了 0.49 ms，接近一个插补周期（1 ms）。2 小时以上的程序，f32 时间会开始丢精度。

2. 真正的瓶颈：i8 量化

这是本次分析最重要的发现。

2.1 数字

窄带 SDF 用 i8 存距离，band = 4 体素、h = 0.1 mm：

表示范围  ±4 × 0.1 = ±0.4 mm
分档      ±127
每档      0.8 / 254 = 3.15 µm
舍入误差  半档 = 1.58 µm

2.2 两项误差，不是一项

量化只是一项。 判定 sdf_stock(p) < 0 要在体素之间插值，所以还有一项三线性重建误差：

误差源 h=0.1 时 与 h 的关系 说明
i8 量化（半档） 1.58 µm ∝ h 值存进去的那一刻就产生了
三线性重建 h²/(8·R_c) ∝ h² 平面上精确；曲面上按曲率增长
合计（最坏，两项同号） 2.0 µm（R_c=3）
曲面曲率半径 R_c 重建误差 合计
平面（∞） 0 1.6 µm
10 mm 0.13 µm 1.7 µm
3 mm（φ6 球刀） 0.42 µm 2.0 µm
1 mm 1.25 µm 2.8 µm
0.5 mm 2.50 µm 4.1 µm
0.25 mm（φ0.5 球刀） 5.00 µm 6.6 µm

所以"1.6 µm 必定检出"只对平面成立。 完整口径：

  • 平面 → 1.6 µm
  • 曲面 R_c ≥ 0.8 mm → 2.0 µm（h=0.1 时插值项恰好不超过量化项的临界曲率是 0.79 mm）
  • R_c < 0.8 mm → 1.6 + h²/(8R_c)，例如 φ0.5 球刀精加工面是 6.6 µm

这条比"1.6 µm"重要得多：小刀具精加工出来的曲面，量化根本不是瓶颈，网格太粗才是。拿"1.6 µm"去承诺 φ0.5 球刀的加工面是错的，差了 4 倍。

2.3 由此得到一条设计规则

要插值项不超过量化项（即总误差不超过 2 倍量化）：

h ≤ √(8 · R_c · 1.575e-3) ≈ 0.11 · √R_c        （h、R_c 单位 mm）

R_c=3 → h ≤ 0.19；R_c=1 → h ≤ 0.11；R_c=0.25 → h ≤ 0.056。

反解"总误差 ≤ ε"的 h 上界，取两项约束的较小者：

h ≤ min( 254·ε / band_voxels ,  √(8·R_c·ε) )
目标 ε 量化限 R_c=3 插值限 取哪个 h=0.1 够吗
2 µm 0.127 0.219 0.127 ✅ 够
1 µm 0.064 0.155 0.064 ❌ 要降到 0.05

这就是"h 一个旋钮控四件事"里最容易漏的第五件：它不只控内存/耗时/采样密度，还通过 h²/(8R_c) 直接控曲面精度。所以"我要验 1 µm 的过切"不能只回答"换 i16"，先看 h 够不够。

2.4 想提精度该花在哪

方案 每档精度 内存（h=0.1） 相对 i8
i8, band=4（现状） 3.15 µm 206 MB 1×
i8, band=2 1.57 µm 206 MB 1×（但窄带太薄，MC 插值不够）
i16, band=4 12.2 nm 412 MB 2× 内存换 258× 精度
f16, band=4 ~0.2 µm 412 MB 2× 换 8×
f32, band=4 48 nm 824 MB 4× 换 65×（不如 i16）

结论：要精度就换 i16，不要换 f64。 换 f64 对 SDF 精度零收益——因为存的是 i8，算的时候转成 float 再转回去，量化误差在存的那一刻就产生了。

i16 做成 GridConfig 的一个选项（value_type: I8 | I16），默认 I8。需要 µm 级验证时切 I16。

4. 为什么标量路径该用 f64

因为它在 x86-64 上几乎免费。

操作 f32 吞吐 f64 吞吐 差异
标量加/乘（SSE2） 1–2 /cycle 1–2 /cycle 无
AVX2 SIMD 8 通道 4 通道 2×

标量 double 和 float 在现代 CPU 上同速——因为 x87 时代早就过去了，SSE2 的标量 double 就是一条指令。f64 的代价只在内存占用和SIMD 宽度上。

所以：

  • 运动学、碰撞：每次调用算几百次浮点运算，量小、精度关键 → f64 免费且更稳
  • SDF 内层：每次调用算几十万次 → SIMD 宽度值 2×，且精度被 i8 限死 → f32

这个分法不是"折中"，是两边的成本收益都算清后的结果。

5. 如果坚持全 f32，会失去什么

诚实地列一下代价：

项 f64 全 f32
RTCP 不变量测试容差 1e-6 mm 需放宽到 1e-4 mm（100 nm）
与 LinuxCNC oracle 对拍 1e-6 做不到（oracle 是 double）
golden 基准精度 1e-12 1e-5
2 小时程序的时间精度 1e-9 s 0.49 ms（半个插补周期）
迭代收敛判据 1e-12 卡在 1e-5，分不清"收敛"与"停滞"

最要命的是第二条：ADR-003 §8.9 用 LinuxCNC 当 oracle 对拍关节值，容差 1e-6。LinuxCNC 内部是 double，我们若用 f32 就永远对不上——这个最有价值的验证手段直接废掉。

所以：标量路径不要省 f64。

6. 一个容易忽略的坑：不要用 float 当索引

// ❌ 错
let idx = (x / h) as f32;
let i = idx as usize;          // 0.1 的累积误差会让 idx 差 1

// ✅ 对
let i = ((x - origin) / h).round() as i32;   // 显式取整，且用 f64 算除法

体素索引必须是整数，且从世界坐标转换时用 f64 做除法再取整。用 f32 在 2000 mm 处 ULP 0.12 µm，若 h = 0.1 mm，x/h 到 20000——f32 在 20000 的 ULP 是 0.0024，取整后可能错 1 格。

错一格就是 0.1 mm 的位置误差，而且只在边界处偶发。

7. 验收口径（修正）

指标 原口径 修正后 原因
碰撞检出下限 0.17 µm 1.6 µm（平面）／2.0 µm（R_c≥0.8 mm）／6.6 µm（φ0.5 球刀面） i8 量化 + 三线性重建
RTCP 不变量 < 1e-6 mm 不变 f64 保持
FK∘IK 往返 < 1e-9 mm 不变 f64 保持
与 LinuxCNC 对拍 < 1e-6 不变 f64 保持
时间精度 — < 1 µs 时间用 f64

i8 → i16 的切换点：只有量化项是主导项时换 i16 才有意义。 换 i16 后量化降到 12 nm，但插值项不动—— h=0.1、R_c=3 时总误差从 2.0 µm 降到 0.42 µm（插值项接管），平面则降到 0.01 µm。 再往下必须降 h（插值项 ∝ h²）：要 0.1 µm 级保证，得 h ≈ 0.05 且 i16，缺一不可。 默认 i8 + h=0.1 覆盖的是"平面 1.6 µm / 常规曲面 2.0 µm"这一档，够铣削验证用。

8. 一句话

float 够用，但问题问错了方向：精度瓶颈在 i8 量化（3.15 µm/档）与三线性重建（h²/(8R_c)），都不在 float 宽度。换 f64 对 SDF 精度零收益；要提精度先降 h（插值项 ∝h²、量化 ∝h），再考虑换 i16（2× 内存换 258× 量化精度）。而标量路径用 f64 是免费的——因为标量 double 和 float 在 x86-64 上同速。
