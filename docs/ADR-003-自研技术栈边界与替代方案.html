ADR-003 自研技术栈：边界、替代方案与代价

自研边界依赖清除

状态：已决策（自研优先，材料去除分两步替换） 修订 2026-10-28：§6 的两步走里"借 cutrail 当运行时脚手架"已作废——按 架构设计 §10，RemovalEngine trait 删除，cutrail 降为 dev-dependency 仅作测试预言机。理由：少一层间接，sim 不必知道"引擎可换"。 日期：2026-10-28 关联：主方案 §2.3 / §2.4、ADR-002

0. 结论

接受"尽可能自研"，但必须先划一条边界，否则项目会死在中途。

三层划分：

层 内容 决策 理由
L0 语言与基础设施 std、serde 不自研 自研序列化框架不产生任何领域价值
L1 引擎与呈现 Bevy、bevy_egui、原生文件对话框 不自研 自研引擎是 2–3 年，等于放弃这个项目
L2 领域内核 数学、运动学、G 代码、材料去除、碰撞、报告 全部自研 这是技术栈的实质，也是唯一值得自研的部分

L2 全自研意味着移除 cutrail、manifold-rust、parry3d、gcode、truck 五个依赖，代价是 40 人日 → 约 159.5 人日。

但有一个重要的副产品：自研路线能给出比 cutrail 更精确的过切判定（§4），因为不再需要网格布尔，改用解析扫掠点测试。ADR-002 里"SDF 撑不住 0.01 mm 判定"的限制被绕过了。

分两步走（§6）：先把 L2 的四个非几何层自研（约 86 人日），材料去除暂时借 cutrail 当脚手架兼测试预言机，跑通后再替换成自研 SDF 内核。

1. 边界原则

1.1 为什么 L1 不自研

"自研技术栈"在 L1 上不是技术选择，是时间黑洞：

  • 自研渲染器（wgpu 管线、材质系统、阴影、PBR）：12–18 个月，而且做完还不如 Bevy。
  • 自研 ECS：3–6 个月，收益为负（Bevy 的 ECS 有 5 年优化）。
  • 自研窗口/输入/文件对话框：2 个月，纯苦力。

这三样加起来 2 年以上，而这个 CNC 工具的全部价值在 L2。

1.2 但 L2 已经是引擎无关的

这是当前架构里最重要的一条保险：cncsim-core / kin / gcode / sim 零 Bevy 依赖（主方案 §3.1）。

所以"自研"的实际含义可以精确表述为：领域层 100% 自有，引擎层可替换。如果将来真要脱离 Bevy，只需重写 render / ui / app 三个 crate，L2 一行不动。

这比"全部自己写"更接近"掌握技术栈"的实质——你掌握的是不可替代的部分。

1.3 判定标准

一个依赖该不该自研，问三个问题：

  1. 它是否包含本项目的领域知识？（是 → 自研）
  2. 它出问题时我能否在一天内定位并绕过？（否 → 考虑自研或 vendor）
  3. 自研它是否超过 3 人周且不产生差异化？（是 → 不自研）

按这三条：运动学、G 代码、材料去除、碰撞全部命中第 1 条；Bevy 命中第 3 条。

3. 材料去除：为什么只能走 SDF

自研材料去除有两条路，代价差 3 倍，风险差一个数量级。

3.1 自研网格布尔：不建议

这是唯一一个我建议明确放弃的自研方向。

理由不是"难"，是已经有人替你试过并且失败了。cutrail 的架构文档原文：

"A B-rep stock updated by one boolean per segment was deliberately not chosen. Machining produces floors at the same depth and walls along the same path on every pass, and B-rep booleans tend to fail on exactly these coincident and touching faces. Trials with several Rust B-rep kernels failed almost every coincident or touching case."

翻译：加工天然产生同深度底面和同路径侧壁，每次走刀都重合。这正是布尔运算最脆弱的退化情形，而它在这个领域是常态而非例外。

Manifold 之所以能撑住（1000 次连续切削无失败），靠的是几十人年的鲁棒性工程（精确谓词、符号扰动、拓扑修复）。自研复现这套，6–12 个月起步，且失败模式是"偶尔产生非流形网格"，极难调试。

结论：不自研网格布尔。要么用 Manifold，要么不用网格布尔。

3.2 自研 SDF 稀疏体素：推荐

代价可控（45 人日），鲁棒性好（体素不存在拓扑退化），且成本与已加工细节无关（ADR-002 §3 已详述）。

设计已在 ADR-002 §3 完成：稀疏 brick + 窄带 i8 距离 + 旋转体母线 SDF + 线性扫掠三分搜索 + CSG max(a, -b) + MC 提取。

自研相比"用现成库"的额外好处：

  • 没有 OpenVDB 那样的 C++ FFI（Rust 生态无成熟等价物）。
  • 内存布局、brick 尺寸、精度都能按 CNC 场景调（而不是通用流体/特效场景的默认值）。
  • 提取出的每 brick 网格可以直接喂 Bevy，不需要格式转换层。

4. 关键补偿：用解析扫掠做判定，而不是用体素

ADR-002 的核心结论是"SDF 撑不住 0.01 mm 级过切判定，因为 MC 把棱边倒圆 h/2"。

自研路线可以绕开这个限制，因为不再需要"用重建出来的网格去比对"，而是直接用解析的刀具扫掠体做点测试。

4.1 原理

过切的定义是：设计曲面上存在被刀具切掉的材料。

所以判定不需要布尔、不需要体素、不需要网格：

在设计曲面上采样，逐点测试"该点是否落在任何一个刀具扫掠体内"。落在里面 = 过切。

这个测试是精确的（浮点精度），误差与体素分辨率无关。

4.2 实现

平底刀沿直线平移的扫掠体，其点包含测试有闭式解：

/// 点是否在某段线性扫掠体内。工具是旋转体，纯平移扫掠体是凸体。
/// 平底刀（圆柱 r × L，刀轴 a，起点 tip0 到终点 tip1）：
///   - 到"沿刀轴无限延伸的圆柱轴"的距离 <= r
///   - 沿刀轴方向的坐标落在 [min, max] 区间内
pub fn point_in_flat_sweep(p: DVec3, tip0: DVec3, tip1: DVec3, axis: DVec3, r: f64, l: f64) -> bool {
    let rel0 = p - tip0;
    let rel1 = p - tip1;
    // 径向：到圆柱轴线的距离
    let radial = |q: DVec3| (q - axis * q.dot(axis)).length();
    // 轴向：相对两个端面刀尖的轴向坐标
    let axial_ok = |q: DVec3| { let t = q.dot(axis); t >= 0.0 && t <= l };
    // 扫掠体 = 两端圆柱的凸包 → 径向取两端最大值即可（凸性保证）
    radial(rel0) <= r && axial_ok(rel0) || radial(rel1) <= r && axial_ok(rel1)
        || {
            // 中间部分：沿线段滑动，等价于到线段距离 <= r 且轴向区间有效
            let (t, _) = closest_param_on_segment(p, tip0, tip1);
            let q = p - tip0.lerp(tip1, t);
            radial(q) <= r && axial_ok(q)
        }
}

球头刀退化成胶囊（到线段距离 ≤ r），圆鼻刀是圆柱 ∪ 环面的并集，都有闭式解。

刀轴在段内旋转（五轴）：按弦高容差切成子段，每子段内刀轴视为定值，测试各子段后取或。这与 cutrail 的旋转细分策略一致。

4.3 代价与精度

项 值
设计曲面采样点 1×10⁵（0.3 mm 网格，200×200 mm 曲面）
每点候选扫掠段（BVH 查询） 约 10
总测试次数 1×10⁶
单次测试 约 50 flops
单线程耗时 约 50 ms（一次性，不随仿真推进增长）
精度 浮点精度（1e-9 mm），与体素无关

这是自研路线的一个净收益：过切判定从"网格比对（受三角化误差影响）"变成"解析点测试（精确）"。

4.4 残留（欠切）不同

残留是"该切掉的没切到"，无法用扫掠体判定（它问的是"哪里没被切"）。残留只能从毛坯形状判断，走体素：

  • 从设计曲面采样点沿外法向发射射线，求与毛坯 SDF 零等值面的距离。
  • 平面区域精度好（三线性插值对平面精确）；棱边附近受 h 影响。
  • 残留量的精度要求本来就低（残留 0.05 mm 和 0.08 mm 对工艺判断没区别），体素够用。

5. 验收口径调整

自研的代价必须体现在验收标准上，否则会在 M4 发现做不到。

# 原口径 自研后口径 原因
A4 去除体积误差 < 1% 不变（体素积分可达 0.3%） 体素体积统计精度足够
A6 过切/残留体积 + 高亮 过切最大深度与位置：±0.001 mm（解析精确）；过切体积：±1%（体素积分） 见 §4
A6' — 新增：残留最大厚度 ±0.05 mm 体素 h=0.1 的固有上限
A9 内存 < 2 GB 内存 < 1 GB（去掉 Manifold 的中间网格后更省） 体素 130 MB + Bevy 场景
— STEP 导入 v1 不支持，v2 再说 去掉 truck；自研 STEP 解析是 4 周以上

产品定位的措辞也要跟着改：从"0.01 mm 级过切验证"改成"过切深度精确、残留厚度 0.05 mm 级、体积与节拍精确"。这个口径对自用完全够——现场判断"这块切多了 3 丝"靠的是过切深度，不是残留厚度。

6. 分两步走

一步到位是 137.5 人日，风险集中在一个还没跑通的内核上。分两步：

第一步：自研四个非几何层（约 86 人日）

cncsim-math     自研 f64 数学              5 人日
cncsim-kin      自研运动学 + LinuxCNC 对照  15 人日
cncsim-gcode    对标 LinuxCNC 的完整解释器    21 人日
cncsim-collide  自研 GJK + 体素判定 + 保守推进  21 人日
cncsim-render/ui/app（Bevy，非自研）        15 人日
────────────────────────────────────────
材料去除：暂时接 cutrail（RemovalEngine trait 隔离）

关键：这一步里 cutrail 扮演双重角色——既是让工具先能用的脚手架，又是自研内核的测试预言机。

用同一批刀路，比较"自研 SDF 的体积/包围盒"与"cutrail 的体积/包围盒"，容差 1%。这与 §8.9 用 LinuxCNC 验证运动学是同一个套路：用一个成熟实现当对照，而不是靠猜。

第二步：替换材料去除（约 45 人日）

cncsim-voxel    稀疏 brick + 窄带 + CSG      18 人日
                旋转体 SDF + 扫掠            10 人日
                MC 提取 + 接 Bevy            7 人日
                解析扫掠点测试（过切）         5 人日
                对拍 cutrail + 性能验收        5 人日
────────────────────────────────────────
验收通过后删除 cutrail 依赖

为什么这个顺序：如果先写体素内核，你会同时面对"运动学对不对"和"内核对不对"两个未知数，出问题时无法二分。先把运动学锁死，体素内核的错误就只剩一个来源。

8. 风险

# 风险 概率 影响 对策
S1 自研 SDF 内核性能不达标 中 高 第二步先做基准再写 MC；brick 间 rayon 并行；不达标时降分辨率而非降精度要求
S2 自研碰撞（GJK/SAT）在退化情形（面接触、边接触）出错 高 中 用"距离阈值 + 保守放大"代替精确接触判定——碰撞检测只需要"小于安全距离"，不需要精确接触流形
S3 自研 f64 数学层引入难以发现的错误 中 高 数学层每个函数配 property test（自研 xorshift + 固定种子，对拍 glam 的 f32 版本，容差放宽）
S4 去掉 STEP 后用户无法导入设计模型 中 中 设计模型用 STL（CAM 软件都能导出）；毛坯用参数化方块/圆柱
S5 总工期翻倍导致中途放弃 中 高 分两步，第一步结束就有可用工具（借 cutrail）；不要一开始就拆桥

S2 值得展开：自研碰撞不要追求精确接触检测。仿真只需要回答"刀柄和毛坯的最小距离是否小于安全间隙"，所以用保守距离（形状放大 0.1 mm 后测相交）即可，避免所有退化情形。这一条省掉了精确接触流形（EPA + 接触点求解，约 6 人日），是 21 人日里最划算的一笔。详见 ADR-004 §2.3。

9. 一句话总结

自研的是领域，不是引擎。L2 全自有、L1 用 Bevy，core/kin/gcode/sim 零引擎依赖——这既满足"掌握技术栈"的实质，也不会让项目死在自研渲染器的第 18 个月。
