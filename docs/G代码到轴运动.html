G 代码如何变成各轴运动

四步流水线弦高容差细分5.963mm 算例2026-10-28

日期：2026-10-28 串起 gcode → kin → sim → render 四层 关联：主方案 §3.3、§4.6；G代码解释器设计.md；机床建模-AC双转台.md

0. 结论

四步，每步的边界都很硬：

G 代码文本
   │ ① gcode：块 → 段（带时间参数化）
   ▼
Vec<Segment>          起点/终点位姿 + 时长 + 插补模式
   │ ② sim：段 → 采样（**插补空间**是核心决策）
   ▼
pose_at(t)            任意时刻的位姿（纯函数，不存储）
   │ ③ kin：位姿 → 关节值
   ▼
q_at(t)               5 个关节值（+ 奇异/限位诊断）
   │ ④ render：关节值 → Transform
   ▼
画面

最关键的一句话：第 ② 步"在哪个空间插补"决定了五轴仿真对不对。

  • RTCP 开 → 在工件空间插补（刀尖走直线），每个周期再做一次逆解
  • RTCP 关 → 在关节空间插补（各轴匀速），刀尖走弧线

选错这一个，误差可以是毫米级（§6 有算例：5.963 mm）。

1. 第一步：块 → 段（cncsim-gcode + cncsim-sim）

MotionProgram 里的 Block 已经是"位姿到位置"，但还没有时间。要变成段，需要算时长。

1.1 段长

运动 段长
G0 / G1 |tip_end − tip_start|
G2 / G3（平面圆弧） R · Δθ
G2 / G3（螺旋） √((R·Δθ)² + Δz²)
G4 停延 由 P/X 给定

注意：段长用的是刀尖走的距离，不是各轴走的距离。五轴联动时两者差很多。

1.2 时长（进给模式决定）

match feed_mode {
    G94 => dur = len / (F / 60.0),              // F: mm/min
    G93 => dur = 1.0 / F,                        // F: 1/min（逆时间）
    G95 => dur = len / (F * spindle_rpm),        // F: mm/rev
}

G93 在五轴里很常见——后处理用逆时间能让刀尖速度在摆动时保持恒定。

1.3 还要算一个"轴速下限时长"

// 由轴速上限反推的最短时间（主方案 §4.7）
let t_min = max over joints of |Δq_j| / v_max_j;
let dur_final = max(dur, t_min);      // 控制器会自动降速

如果 t_min > dur，说明这段被轴速卡住了——记一条 KIN-00x 警告，报告里体现"实际进给低于程序值"。

2. 第二步：段 → 采样（cncsim-sim，核心）

2.1 插补空间：这是五轴仿真的分水岭

同一个段，两种插补方式给出完全不同的刀尖轨迹：

RTCP 开（G43.4） RTCP 关
插补对象 位姿（刀尖位置 + 刀轴方向） 关节值
刀尖轨迹 工件空间里的直线 空间曲线
每个周期要做 位姿插值 → 逆解 直接给关节值
谁在用 现代五轴控制器 3+2 定位、老式控制器 
pub enum InterpSpace {
    /// RTCP 开：位姿空间插补，每周期逆解
    Pose,
    /// RTCP 关：关节空间插补，直接得到 q
    Joint,
}

这不是"精度选项"，是语义区别。 程序里写了 G43.4 就该用 Pose，没写就该用 Joint——用错的话仿真的不是同一个程序。

2.2 位姿插补要分开处理位置和姿态

fn pose_at(seg: &Segment, t: f64) -> Pose {
    let s = t / seg.dur;                       // 归一化 0..1
    Pose {
        tip:  seg.tip_start.lerp(seg.tip_end, s),      // 位置：线性
        axis: slerp(seg.axis_start, seg.axis_end, s),  // 姿态：球面插值
    }
}

姿态必须用 slerp 不能用 lerp + 归一化。 后者角速度不均匀——在两端慢中间快，会让仿真的非线性误差算错。

fn slerp(a: DVec3, b: DVec3, s: f64) -> DVec3 {
    let dot = a.dot(b).clamp(-1.0, 1.0);
    let theta = dot.acos();
    if theta < 1e-9 { return a; }
    let (sa, sb) = ((1.0 - s) * theta, s * theta);
    (a * sa.sin() + b * sb.sin()) / theta.sin()
}

边界情况：a 与 b 几乎反向（dot ≈ -1）时 slerp 无定义——五轴机不会出现（刀轴不会翻转 180°），但要断言。

2.3 采样密度：弦高容差，不是固定 1 ms

修正：本节初版说"选固定 1 ms 采样，跟控制器行为一致"。这个理由不成立——需要控制器行为的三个量（非线性误差、轴速降额、伺服周期）都有闭式公式，不需要逐周期采样。按 1 ms 算，3 秒段要 3000 子步，10 万段要跑 16.7 小时。详见 点位预读与流水线缓冲.md §2。

刀轴在段内旋转时，扫掠体的真实表面是曲面。用两个姿态的凸包近似会有弦高误差：

弦高 ≈ R · (1 − cos(Δθ/2))          // 与非线性误差同一个公式，都是弧与弦的拱高

要求弦高 ≤ ε，得每子步最大转角 Δθ_max = 2·acos(1−ε/R)，于是：

子步数 n = ceil( Δθ_segment / Δθ_max )

R = 175 mm、ε = 0.01 mm 时 Δθ_max = 1.23°：

段内摆角 子步数
5° 5
15° 13
30° 25
60° 49

对比固定 1 ms 的 3000 子步——少 120 倍。

2.4 点位不存储，流式消费

关键：点位不存储，流式消费。

即使按弦高容差，10 万段 × 25 点 = 250 万点 × 104 B ≈ 260 MB——能存但没必要。而且改参数时要全部作废。

所以：

// 仿真线程：逐子步消费，直接喂给 voxel / collide，不保留
for pt in point_stream {                  // 生产者按弦高容差预读
    voxel.cut(&tool, &prev_pose, &pt.pose);   // 去料
    collide.check(&pt.q, &pt.pose);            // 碰撞
    prev_pose = pt.pose;
}

回放时按需重算（§4），不查表。

生产比消费快约 200 倍，所以缓冲只需 256 点（27 KB）——"预读充足"的判据是"消费者永不空转"，不是"越多越好"。

3. 第三步：位姿 → 关节值（cncsim-kin）

3.1 每个采样做一次逆解

摇篮机的 RTCP 逆解（机床建模-AC双转台.md §3.3）：

u = x·cosC − y·sinC
v = x·sinC + y·cosC
X = u
Y = v·cosA − (z+L)·sinA
Z = v·sinA + (z+L)·cosA

A、C 从哪来？ 由刀轴方向反解（§5 of 建模文档）：

n_W = (sinA·sinC,  sinA·cosC,  cosA)
→ A = acos(n_z)
→ C = atan2(n_x, n_y)          // 注意是 (nx, ny) 不是 (nx, -ny)

3.2 三件必须做的事

（1）多解选择：取离上一周期最近的那个

atan2 给的是 (-π, π]，但 C 轴可以连续转。如果每周期都取主值，C 轴会在 ±180° 处来回跳。

let c_raw = n.x.atan2(n.y);                    // 主值
let c = nearest_wrap(c_raw, prev_c);           // 展开到上一值附近

这是"关节值看起来乱跳"的最常见原因。

（2）奇异点：保持上一值，不要跳变

A ≈ 0 时 C 无定义。控制器行为是保持 C 不动，不是跳到 0 或 180。

if a.sin().abs() < 1e-3 {
    c = prev_c;                                 // 保持
    diag.push(KinFinding::Singularity { at: t });
}

（3）轴限位检查

for (j, &val) in q.iter().enumerate() {
    if !joint[j].limit.contains(val) {
        diag.push(KinFinding::AxisLimit { joint: j, value: val });
    }
}

真实控制器会在这里报警停机；仿真器记一条 KIN-00x 并标 Trust::Unreliable。

4. 第四步：关节值 → 动画（cncsim-render）

4.1 回放时重新算，不查表

fn update_joints(time: f64, program: &MotionProgram, kin: &Machine, q: &mut [f64]) {
    let seg = program.segment_at(time);          // O(log n) 二分
    let pose = pose_at(seg, time);               // 与计算线程同一个函数
    kin.inverse_into(pose, q);                   // 就地写，不分配
}

必须与计算线程用同一个 pose_at。 否则"看到的"和"算的"不是一回事——画面在骗人。

成本：每帧 1 次 IK，微秒级，可忽略。

4.2 帧率 ≠ 插补周期

周期
仿真采样 1 ms
显示刷新 16.7 ms（60 fps）

回放时直接求 t 时刻的位姿，不需要"在采样点之间插值"——因为 pose_at 本身就是连续的。这比"存采样点再插值"更准，也更省内存。

4.3 只更新变化的关节

for (i, &val) in q.iter().enumerate() {
    if (val - prev_q[i]).abs() > 1e-9 {
        joint_entity[i].transform.rotation = ...;   // 只改变了的
    }
}

五个关节里通常只有 1–2 个在动，全量更新会让 Bevy 的变更检测失效（所有子实体都标记脏）。

5. 一个完整算例（带数字）

摇篮机，L = 180，插补周期 1 ms。

块：G1 X0 Y0 Z-5 A0 C0 → X50 Y0 Z-5 A30 C0 F1000（RTCP 开）

5.1 第一步：段

刀尖段长 = 50 mm
时长     = 50 / (1000/60) = 3.0 s
子步数   = 25（弦高容差 0.01 mm、摆 30°）

5.2 第二步：采样（RTCP 开 → 位姿插补）

起点位姿：tip=(0,0,-5)，axis=(0,0,1)（A=0） 终点位姿：tip=(50,0,-5)，axis=(0, 0.5, 0.866)（A=30）

中点 t=1.5s（s=0.5）：

tip  = (25, 0, -5)
axis = slerp((0,0,1),(0,0.5,0.866),0.5) = (0, sin15°, cos15°) = (0, 0.2588, 0.9659)
     → A = 15°, C = 0

5.3 第三步：逆解

z + L = -5 + 180 = 175
u = 25, v = 0

X = 25
Y = 0 − 175·sin15° = −45.29
Z = 0 + 175·cos15° = 169.03

三个关键时刻的关节值：

t X Y Z A
0 0 0 175.00 0°
1.5 25 −45.29 169.03 15°
3.0 50 −87.50 151.55 30°

Y 和 Z 都在走曲线——这就是 RTCP 补偿：刀尖走直线，机床轴走弧线。

5.4 对照：如果 RTCP 关（关节空间插补）

把上面三行的关节值线性插值，中点得到：

q(1.5) = (25, −43.75, 163.28, 15°, 0)

用 FK 算刀尖（tip = (X, Y·cosA + Z·sinA, −Y·sinA + Z·cosA − L)）：

y = −43.75×0.9659 + 163.28×0.2588 = −42.26 + 42.26 = 0     ✓
z = 43.75×0.2588 + 163.28×0.9659 − 180 = 11.32 + 157.71 − 180 = −10.97

刀尖在 (25, 0, −10.97)，而应该在 (25, 0, −5)——偏了 5.963 mm。

这就是为什么五轴必须开 RTCP：同样的程序，不开 RTCP 会过切近 6 mm。

6. 非线性误差的公式（从算例里提炼）

上面那个 5.963 mm 不是巧合。一般地：

非线性误差 ≈ R · (1 − cos(Δθ/2))

其中 R = 刀尖到回转中心的距离，Δθ = 这一段里转过的角度。

推导：关节空间插补时，刀尖沿圆弧走（半径 R，张角 Δθ），而意图是弦。弧与弦的最大距离就是拱高 R(1−cos(Δθ/2))。

验证算例：R = 175，Δθ = 30° → 175 × (1 − cos15°) = 175 × 0.03407 = 5.963 mm ✓

6.1 这个公式直接给出"后处理要多密"

要求非线性误差 < ε：

Δθ_max = 2 · acos(1 − ε/R)

R = 175 mm 时：

目标误差 ε 每段最大摆角 Δθ 摆长 175 上每段弧长
0.1 mm 3.9° 11.9 mm
0.01 mm 1.22° 3.7 mm
0.001 mm 0.39° 1.2 mm

这就是后处理"点位密度"的硬指标：摆长 175 的摇篮机，要把非线性误差控制在 10 µm，每段摆角不能超过 1.2°（弧长 3.7 mm）。

后处理给的密，误差就小；给的稀，误差就大——而这个误差在仿真里必须能报出来，否则用户不知道自己的后处理有问题。

6.2 这就是"非线性误差"在链路里的位置

它不是一个后处理的分析步骤，而是第 ② 步选错插补空间的直接后果。所以仿真器要：

  1. 按程序的 RTCP 状态选插补空间（诚实模拟）
  2. 同时算"理想直线"与"实际轨迹"的偏差
  3. 逐段报出最大偏差与位置（主方案 §4.6）

7. 三个必须决定的点

# 问题 建议 理由
1 插补空间由什么决定？ 由程序的 G43.4 状态自动决定，不设开关 用错就仿真的不是同一个程序
2 采样密度固定还是自适应？ 按弦高容差自适应（Δθ_max = 2·acos(1−ε/R)） 固定 1 ms 会多算 120 倍（§2.3），而控制器行为可用闭式公式表达
3 采样点存不存？ 不存，计算流式消费、回放按需重算 250 万点 260 MB，且改参数全作废

第 2 点的取舍要展开一句："模拟控制器行为"和"几何精度"是两件事。控制器行为（非线性误差、轴速降额）有闭式公式，用端点就能算；几何精度（扫掠体细分）由弦高容差定。两者都不需要固定周期采样。

第 3 点是架构上最重要的一条——它把"内存爆炸"变成"每帧一次 IK"。

8. 与 crate 的对应

步骤 crate 产物
① 块 → 段 gcode（解析）+ sim（算时长） Vec<Segment>
② 段 → 采样 sim（pose_at） 流式 Pose
③ 位姿 → 关节 kin（inverse） [f64; 5] + KinFinding
④ 关节 → 画面 render Transform

pose_at 住在 sim 里，gcode 与 render 都能用——这是保证"看到的 = 算的"的关键。render 依赖 sim 正是为此。

10. 一句话

G 代码到轴运动，本质是一个"时间参数化 + 逐周期逆解"的过程。 唯一容易做错的是插补空间——RTCP 开在位姿空间插补、关在关节空间插补，这一条错了，误差是毫米级（算例：5.963 mm），而画面看起来完全正常。
