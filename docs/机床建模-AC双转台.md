## 1. 为什么选这个构型

| 构型 | 叫法 | 特点 |
|---|---|---|
| **AC 双转台** | **摇篮式** | 工件转、刀具不转；刚性好；**国产五轴加工中心主流** |
| AC 摆头 | 摆头式 | 刀具转、工件不转；适合大件 |
| 摆头+转台 | 复合式 | 两者都转；最灵活、最复杂 |

选摇篮式：它的运动学与摆头式**镜像**（工件坐标系在动，不是刀具坐标系在动）——主方案 §4 与附录 A 推的都是摆头式，这里补上另一半。而且它有一个摆头式没有的现象：**摆动会吃掉直线轴行程和速度**（§6），直接影响节拍。

## 2. 坐标系与唯一的几何参数

```
机床坐标系 M：Z=0 取在 A 轴（摇篮轴）中心高度，X/Y=0 在 C 轴轴线上
工件坐标系 W：原点在 C 转台台面中心，随转台一起转（即 G54）
```

| 符号 | 含义 | 取值 |
|---|---|---|
| **`L`** | **A 轴中心 → C 转台台面的距离** | **180 mm** |
| `D` | 工作台直径 | 400 mm |

**关键结论：摇篮式的运动学只有一个几何参数 `L`。**

常被误当成参数的是"机床 Z 参考面到 A 轴中心的距离 H"——它只影响机床的绝对高度和行程范围，**不影响刀尖相对工件的位姿**。把 Z=0 定在 A 轴中心，`H` 就被基准选择吸收了。这一点值得记住：**少一个参数就少一个错的地方**。

装配关系（全部几何的来源）：

- C 转台台面在 A 轴中心**上方 `L`**，台面朝向 +Z（A=0 时）
- C 绕自身法线（A=0 时即 +Z）旋转
- A 绕 X 轴旋转，枢轴就是机床原点

## 3. 齐次变换链

### 3.1 工件 → 刀具

我们的 `MachineTopology.chain` 是「工件 → 刀具」的连乘，每项为 `Translate(offset) · Rotate(q)`：

```
T_WT = Rz(−C) · T(0,0,−L) · Rx(−A) · T(X,Y,Z)
```

从右往左读：

1. `T(X,Y,Z)`：直线轴把主轴移到机床坐标（在机床系里）
2. `Rx(−A)`：**反向**转回摇篮（工件转了 +A，工具在工件系里就转 −A）
3. `T(0,0,−L)`：从台面中心退到 A 轴中心
4. `Rz(−C)`：**反向**转回 C 转台

**两个 `sign = −1` 是推导出来的，不是猜的**：工件转了 +A，要表达"刀尖在工件坐标系里在哪"，就必须用逆变换 −A。这正是 `Joint::sign` 字段的用途。

### 3.2 正解

```
刀尖在工件系：  p_W = T_WT · (0,0,0)
刀轴在工件系：  n_W = R_WT · ẑ            （n 由刀尖指向主轴，A=0 时为 +Z）
```

### 3.3 逆解 / RTCP

RTCP 模式（G43.4）下，程序给的 `X/Y/Z` 是**工件坐标系里的刀尖位置**，控制器反算机床直线轴：

```
u = x·cosC − y·sinC
v = x·sinC + y·cosC

X = u
Y = v·cosA − (z + L)·sinA
Z = v·sinA + (z + L)·cosA
```

**注意是 `(z + L)` 不是 `(z − L)`**：刀尖到 A 轴中心的轴向距离是 `z + L`（工件原点在 A 轴中心上方 L，刀尖在 z 处）。

这个式子可以一句话概括：

> **（Y, Z）就是把 (v, z+L) 绕 X 轴转 −A。**

## 5. 奇异点

展开 `n_W = Rz(−C)·Rx(−A)·ẑ`：

```
n_W = ( sinA·sinC,  sinA·cosC,  cosA )
```

- `A = 0` → `n_W = (0,0,1)`：刀轴与 C 轴平行
- 此时 C 变化**不改变刀轴姿态**，只让工件绕刀轴自转 → **C 对刀轴无影响，逆解不唯一**

**摇篮式的这个奇异点比摆头式温和**：摆头式在 A=0 时 C 失控会让刀轴突跳；摇篮式只是"工件绕刀轴自转"，加工本身仍然正确（相当于车削）。

真正的麻烦在近奇异区的速度耦合，见 §6.2。

## 6. 摇篮式特有：摆动吃掉行程与速度

### 6.1 行程耦合（实测）

刀尖在台面中心（`p_W = (0,0,0)`）时，RTCP 求出的直线轴位置：

| A | X | Y | Z | ΔY | ΔZ |
|---|---|---|---|---|---|
| 0° | 0 | 0 | 180.0 | 0 | 0 |
| 30° | 0 | −90.0 | 155.9 | −90.0 | −24.1 |
| 60° | 0 | −155.9 | 90.0 | −155.9 | −90.0 |
| 90° | 0 | −180.0 | 0.0 | −180.0 | −180.0 |
| **110°** | 0 | **−169.1** | **−61.6** | **−169.1** | **−241.6** |

**含义**：A 摆到 ±110° 时，Y 要额外走 169 mm、Z 要额外下沉 242 mm。**这部分行程纯补偿，不产生任何切削**。

设计机床时行程必须包含它，否则会出现"标称行程够、实际摆不到位"。仿真器应当直接检查这一条——这是用户最容易忽略的撞机原因之一。

### 6.2 速度耦合（更严重）

`Y = v·cosA − (z+L)·sinA` 对时间求导（`v`、`z` 固定）：

```
dY/dt = −(z+L)·cosA · dA/dt
```

刀尖在台面（`z = −L`，故 `z+L = 0`）时该项为零——**贴着台面转不消耗 Y 轴速度**。

但刀尖抬高 50 mm（`z+L = 50`）、A 轴 25 rpm：

```
|dY/dt| = 50 × 2.618 = 131 mm/s = 7.9 m/min
```

刀尖抬高 180 mm 时：

```
|dY/dt| = 180 × 2.618 = 471 mm/s = 28.3 m/min
```

**这个数是摇篮机的固有短板**：A 在 0 附近摆动时 Y/Z 补偿速度最大，已经接近很多机床的快移速度（30 m/min），控制器被迫降速，实际进给远低于程序值。

仿真器应报出："第 N 段要求 Y 轴 28.3 m/min，达机床上限的 94%，实际进给降至 88%"——这正是主方案 §4.7「轴速超限」要输出的东西。

## 9. `.machine.ron`

```ron
(
  name: "AC 双转台摇篮（L=180）",
  chain: [
    // 工件端：两个旋转轴，sign = −1 是因为要表达"工具在工件系"
    (name:"C", kind:Rotary(Z), offset:(0,0,0),    pivot:(0,0,0), sign:-1.0, limit:(-99999, 99999)),
    (name:"A", kind:Rotary(X), offset:(0,0,-L),   pivot:(0,0,0), sign:-1.0, limit:(-110, 110)),
    // 机床端：三个直线轴，在机床系里，sign = +1
    (name:"X", kind:Linear(X), offset:(0,0,0),    pivot:(0,0,0), sign: 1.0, limit:(-400, 400)),
    (name:"Y", kind:Linear(Y), offset:(0,0,0),    pivot:(0,0,0), sign: 1.0, limit:(-300, 300)),
    (name:"Z", kind:Linear(Z), offset:(0,0,0),    pivot:(0,0,0), sign: 1.0, limit:(-120, 520)),
  ],
  tool_length: 0.0,      // 刀尖即链末端，长度由刀具表另给
  pivot_distance: (0,0,0),
)
```

**三个要点**：

1. **链的顺序是 C → A → X → Y → Z**（旋转轴在前）——摇篮式的旋转轴在**工件端**，与摆头式相反。这是两种构型在配置层面的唯一区别。
2. **`A` 的 `offset` 是 `(0,0,−L)`**——从台面中心退到 A 轴中心，且必须在 A 旋转**之前**（我们的 FK 正是先 `Translate(offset)` 再旋转）。
3. **`sign` 全部由推导确定**：工件端的两个旋转取 −1，机床端的直线轴取 +1。

## 10. 与摆头式的对照

| | AC 摆头（主方案附录 A） | **AC 双转台（本文）** |
|---|---|---|
| 谁在动 | 刀具 | 工件 |
| 链顺序 | X→Y→Z→C→A | **C→A→X→Y→Z** |
| 刀轴 `n_W` | `(sinA·sinC, −sinA·cosC, cosA)` | `(sinA·sinC, sinA·cosC, cosA)` |
| 奇异点后果 | 刀轴突跳（危险） | 工件绕刀轴自转（温和） |
| 固有短板 | 摆头刚度 | **摆动吃行程与速度** |

**注意两个 `n_W` 的 Y 分量符号相反**——这正是"抄公式最容易抄错"的地方，必须靠各自的锚点测试锁定。

## 11. 本次修正的两个错误（留档）

手算锚点与程序结果对不上，查出两处：

| # | 错误 | 正确 | 后果 |
|---|---|---|---|
| 1 | RTCP 里用 `(z − L)` | **`(z + L)`** | 摆长方向反了，Z 轴整体偏移 2L = 360 mm |
| 2 | `n_W` 的 Y 分量写成 `−sinA·cosC` | **`+sinA·cosC`** | 刀轴绕 Z 镜像，C 转 90° 时方向完全错 |

第 1 个尤其隐蔽：它只让 Z 整体偏 360 mm，而**画面看起来完全正常**——正是反复强调的那类 bug。**如果没有数值验证，这两个错误都会直接进代码。**

教训：**手推公式之后必须用独立实现（齐次矩阵连乘）跑一遍锚点**，两者一致才算数。

## 12. 加工包络（轴行程 ≠ 加工范围）

这是用户最常问、也最容易答错的问题。**直接把 X/Y/Z 行程报出去是错的**——摇篮式机床摆动时，直线轴要额外走补偿行程（§6.1），所以**可用包络随摆角急剧变化**。

### 12.1 轴行程（原始参数）

| 轴 | 行程 |
|---|---|
| X | −400 … +400 mm |
| Y | −300 … +300 mm |
| Z | −120 … +520 mm（**Z=0 是 A 轴中心高度**，台面在 Z=+180） |
| A | −110 … +110° |
| C | 连续 |

### 12.2 实际可用高度（算出来的）

设工件为 Φ400（占满转台）的圆柱，求"给定摆角下能加工的最大工件高度"——即工件最不利点（半径 200 处的顶点）仍能被刀尖到达。

| 摆角 A | 最大工件高度 | 约束来自 |
|---|---|---|
| 0° | **340 mm** | Z 上限 |
| 15° | 399 mm | Y |
| **30°** | **420 mm**（峰值） | Y |
| 45° | 397 mm | Y |
| 60° | 281 mm | Y |
| 75° | 184 mm | Y |
| **90°** | **120 mm**（最紧） | **Y** |
| 105° | 140 mm | Y |
| 110° | 139 mm | Y |

> 上表由 [`tools/envelope.py`](../tools/envelope.py) 计算，已与独立的手算结果对照。

**两个反直觉的结论**：

1. **A=30° 时可用高度最大（420 mm），比 A=0 的 340 还高。** 因为工件倾斜后，顶点向侧上方移动，反而落进了 Z 行程的富余区。
2. **A=90° 时只剩 120 mm。** 台面竖直后，工件沿自身轴线伸出 180 mm（= L）就已经吃掉全部 Y 行程——**Y 行程成了瓶颈，不是 Z**。

### 12.3 三条必须说清的限制

**(a) 这是"点可达"，不是"能加工"**

上表只保证刀尖能到那个点。**没算碰撞**：摆到 90° 时刀柄会撞转台、撞工件侧壁。真实可用包络比表里更小。

**(b) 没有安全余量**

表里的数字是**贴着行程极限**算的。实际排工艺至少要留 10–20% 余量，否则一个编程误差就撞限位。

**(c) 工件必须居中**

上表假设工件轴线与 C 轴重合。如果偏置装夹（偏移 d），可用高度会明显下降——因为 `v` 的可用范围被偏置占用了一半。

### 12.4 与摆头式对比

同规模下摆头式的包络更"方"：

| | AC 双转台（本机） | LinuxCNC XYZBC 摆头（`refs/linuxcnc/`） |
|---|---|---|
| 行程 | X±400 Y±300 Z−120…520 | X±500 Y±500 Z−500…100 |
| 摆角 | A±110° | B±120° |
| **摆动是否吃行程** | **是（Y/Z 被吃掉）** | 否（刀具转，工件不动） |
| 包络形状 | 随摆角剧烈变化 | 基本是长方体 |

**这就是摇篮机与摆头机的本质区别**：摇篮机的"加工范围"不是一个盒子，而是**一组随姿态变化的盒子**。报价/排工艺时必须按实际摆角查表，不能用标称行程。

### 12.5 怎么在软件里呈现

仿真器应该把这个包络**画出来**：

- 3D 视图里叠一层半透明的"可达包络"网格
- 拖动 A 轴时包络实时变化
- 工件超出包络时高亮报警（`KIN-00x` 轴限位）

这比让用户去查表直观得多，也避免了"标称行程够、实际摆不到位"这类撞机。

### 12.6 计算工具：`tools/envelope.py`

```bash
python tools/envelope.py                                    # 默认读 ac_trunnion 配置
python tools/envelope.py --radius 150 --angles 0,45,90      # 换工件半径与角度
python tools/envelope.py --csv envelope.csv                 # 导出供画图
```

**原理：只用正解，不需要逆解。**

对固定的旋转角 `(A, C)`，直线轴 `X/Y/Z` 在限位内的可达集合，在工件坐标系里是**一个仿射映射后的长方体**（8 个角点即可确定）。于是每个 `(A, C)` 对应一个平行六面体，**包络 = 它们的并集**。

判据：工件（半径 R、高 h 的圆柱）可加工 ⟺ 其表面每个点都落在某个平行六面体内。

**离散化的方向是安全的**：`C` 采样 72 档时结果已收敛（`C=36` 会把 A=30° 从 420 低估到 410）。**低估 = 不会过度承诺**，这比高估安全。

### 12.7 一个容易搞错的约定：`tip_w` 是链乘积的平移部分

写这个工具时踩了一个坑，值得记下来。

直觉上"刀尖在工件系的位置"应该是 `T⁻¹ · 0 = −Rᵀt`。**但那是错的。**

因为 RON 里旋转轴的 `sign = −1`，链乘积实际是**「刀具 → 工件」**的变换（不是「工件 → 刀具」）。所以：

```
tip_w = T 的平移部分 t          ← 正确
tip_w = −Rᵀ·t                   ← 错，会在 A=90° 时把 Y 的符号搞反
```

这与 `tools/verify_trunnion.py` 的 `tip = t[:3,3]` 一致，且已被 §4 的三个锚点确认。

**教训**：`MachineTopology.chain` 的文档写"工件 → 刀具"是描述**物理装配顺序**，而矩阵乘积的方向相反（由 `sign = −1` 实现）。这个不一致必须在 `kin` 的实现注释里写清，否则很容易在写第二个消费者（包络、碰撞、渲染）时搞反。
