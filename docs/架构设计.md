# CNCSIM 架构设计

> 日期：2026-10-28
> 目标：模块化、高内聚、低耦合，且**耦合约束可机器校验**
> 替代：主方案 §3.1 的初版分层

---

## 0. 先说初版分层错在哪

主方案 §3.1 是这么分的：

```
cncsim-app / ui / render / sim / kin / gcode / core
```

两处硬伤：

| # | 问题 | 后果 |
|---|---|---|
| 1 | **`cncsim-core` 是个"类型垃圾场"** | 凡是两个 crate 都要用的类型就往里塞。它会被所有 crate 依赖（高扇入），但内部没有任何内聚的概念——**这是低内聚的典型形态，却伪装成"公共层"** |
| 2 | **`cncsim-sim` 是个杂货铺** | 去除调度 + 碰撞 + 精度比对 + 节拍统计，四个不相干的关注点挤在一个 crate 里 |

改法：

- **删掉 `core`**。公共类型按**概念簇**拆成三个小 crate：`math`（数学）、`motion`（运动）、`tool`（刀具）。每个都只服务一个概念。
- **拆掉 `sim`**。几何内核（`voxel` / `collide`）独立成层；`sim` 只留"编排"，即把各层按时间顺序驱动起来。
- 补上 ADR-003/006 里已经存在但分层图没体现的 `voxel` / `collide` / `math`。

## 1. 分层与 crate 清单

```
L5 装配    cncsim-app
              │
L4 呈现    cncsim-render ──┐   cncsim-ui ──┐
              │            │       │       │
L3.5 控制              cncsim-hmi ─┘       │
                       │                   │
L3 编排    └────────── cncsim-sim ─────────┘
                       │
        ┌──────────────┼──────────────┐
L2 几何内核  cncsim-voxel      cncsim-collide
        │              │              │
L1 领域算法  cncsim-kin ────┴── cncsim-gcode
        │              │              │
L0 词汇    cncsim-motion ── cncsim-tool
                       │
基座       cncsim-math
```

| crate | 一句话职责 | 依赖 |
|---|---|---|
| **`cncsim-math`** | f64 线性代数：`DVec3 / DMat4 / DQuat / 最小二乘` | **无** |
| **`cncsim-config`** | 磁盘格式：`.machine.ron` → `MachineTopology`（**输入适配器**） | math, kin |
| **`cncsim-motion`** | 运动词汇：`Pose`、`MotionSegment`、进给模式、时间戳 | math |
| **`cncsim-tool`** | 刀具词汇：母线 profile、`CutterKind`、刀柄 | math |
| **`cncsim-kin`** | 关节值 ↔ 刀位：拓扑、FK、解耦 IK、RTCP、奇异点 | math, motion |
| **`cncsim-gcode`** | 文本 ↔ 运动程序：词法、模态机、方言 | math, motion, tool |
| **`cncsim-cam`** | 工艺生成：三角网格 → 3 轴高度场刀路 / **A/C 回转 RTCP 刀路** → G 代码（**不依赖 voxel/sim**） | math, tool |
| **`cncsim-voxel`** | 实体表示与 CSG：稀疏树、解析 SDF、扫掠、MC 提取、STL 解析、网格体素化 | math, motion, tool |
| **`cncsim-collide`** | 相交判定：GJK、凸体、保守推进、检出保证 | math, motion, tool |
| **`cncsim-sim`** | 编排：仿真调度、回放缓冲、后台线程、报告聚合 | 以上全部 |
| **`cncsim-hmi`** | 人机控制：状态机、急停、倍率、报警队列 | math, sim |
| **`cncsim-render`** | Bevy 插件：场景、毛坯网格、剖切、着色 | math, motion, tool, voxel, sim |
| **`cncsim-ui`** | bevy_egui 面板：时间轴、机床树、报告 | math, **hmi**（不直连 sim） |
| **`cncsim-app`** | 装配：窗口、CLI、文件 I/O | 全部 |

**14 个 crate 会不会太多？** 判断标准是"删掉它之后耦合会不会变高"：

- 删 `motion` → `kin` 和 `gcode` 必须互相依赖或各自定义 `Pose`，耦合升高 ✓ 保留
- 删 `tool` → `voxel` 和 `collide` 各自定义刀具，两份会漂移 ✓ 保留
- 删 `collide` → `sim` 里塞进 GJK 和保守推进，回到杂货铺 ✓ 保留
- 删 `ui` → `render` 里塞进 egui，呈现层职责混杂 ✓ 保留
- 删 `cam` → `app` 里塞进高度场/刀路/后处理，**生成器和验证器互相依赖**，无法独立测 ✓ 保留
- 删 `hmi` → 控制状态机塞进 `ui`，**headless 批处理就没有急停/倍率/报警**；塞进 `sim` 则仿真调度与操作语义混在一起 ✓ 保留
- 删 `config` → `kin` 就得读整个 `.ron`，于是它必须知道 `Shape::Box` 和 `ColliderSpec::Derived`，**L1 算法层被磁盘格式污染**；或者 `app` 里手写解析，各层共享的字段定义无处安放 ✓ 保留

每一个都满足"删了就变差"。

## 2. 依赖规则

### 2.1 硬规则

1. **只能向下依赖**，禁止反向与横向。
2. **`kin` 不知道 `voxel` 存在；`voxel` 不知道 `kin` 存在。** 只有 `sim` 同时知道两者。
3. **L0–L3 零 Bevy 依赖**（`cargo tree` 里不出现 bevy）。
4. **禁止"公共类型 crate"**。新增共享类型时，先问它属于哪个概念簇；答不出来说明设计没想清，不要新建 `core`。

### 2.2 允许的边（白名单）

```
math     → (无)
config   → math, kin            ← 输入适配器；kin 反过来不认识 .ron
motion   → math
tool     → math
kin      → math, motion
gcode    → math, motion, tool
cam      → math, tool            ← 只出 G 代码文本；解释/仿真在 app/sim
            │  3 轴：高度场 → Z 层行切 + 平行精加工
            └  5 轴：细网格真值轮廓 → 径向让刀粗加工 + 法向摆角精加工（G43.4）
voxel    → math, motion, tool
collide  → math, motion, tool
sim      → math, motion, tool, kin, gcode, voxel, collide
hmi      → math, sim
render   → math, motion, tool, voxel, sim
ui       → math, hmi          ← 不直连 sim
app      → 全部
```

**除白名单外一律视为违规。** `tools/check_deps.py` 会读每个 crate 的 `Cargo.toml` 逐条核对，违反则 CI 失败。

### 2.3 两条关键的"解耦"设计

**（a）`collide` 不依赖 `voxel`——用 trait 反转**

碰撞要查毛坯距离场，但若 `collide → voxel`，两者就绑死了。改成：

```rust
// 定义在 collide 里，由 voxel 实现
pub trait DistanceField {
    /// 有符号距离。正值在材料外。
    fn sdf(&self, p: DVec3) -> f64;
    /// 带宽外返回钳制值（供粗筛判断"足够远"）
    fn band(&self) -> f64;
}
```

好处有三个：

1. `collide` 可以脱离 `voxel` 单独测试——**直接用解析半空间做假实现**，这正是 ADR-004 §7.7 那条"圆柱 vs 半空间"随机对拍需要的。
2. 将来换体素结构（比如换分辨率策略）不影响 `collide`。
3. `voxel` 不知道自己被碰撞用着，可以独立演进。

**（b）不建共享的 `Diagnostic` 枚举**

`kin` 报奇异点、`collide` 报碰撞、`gcode` 报解析失败。如果都塞进一个底层 `Diagnostic`，那个枚举就成了第二个"垃圾场"。

改成**各层自带 finding 类型，`sim` 组合**：

```rust
// kin 里
pub enum KinFinding { Singularity { .. }, AxisLimit { .. }, FeedDeviation { .. } }
// collide 里
pub struct CollisionEpisode { .. }
// gcode 里
pub struct ParseIssue { .. }

// sim 里——只有它同时知道三者
pub enum Diagnostic {
    Kin(kin::KinFinding),
    Collision(collide::CollisionEpisode),
    Parse(gcode::ParseIssue),
}
```

底层互不相识，编排层负责组装。**这是"低耦合"最实用的一条：不要在底层造共享词汇，让上层组合。**

## 3. 每个 crate 的边界（做什么 / 不做什么）

### `cncsim-math`
- **做**：`DVec3 / DMat4 / DQuat`、`Transform` 组合、最小二乘、矩阵求逆
- **不做**：任何 CNC 概念；不引入 `glam`（渲染边界才转 f32）

### `cncsim-motion`
- **做**：`Pose { tip: DVec3, axis: DVec3 }`、`MotionSegment`（直线/圆弧）、`FeedMode`、单位约定
- **不做**：不解析 G 代码、不算运动学
- **必须钉死的约定**：`Pose.axis` 是**单位向量，方向由刀尖指向主轴**（A=0 时为 +Z）。全项目只此一种约定，用测试锁住

### `cncsim-tool`
- **做**：母线 profile（ρ,z 折线）、`CutterKind`、刃长、刀柄轮廓、`sd_profile` 的**几何定义**
- **不做**：不做碰撞分解、不做扫掠

### `cncsim-kin`
- **做**：`MachineTopology`、FK、解耦 IK、RTCP、奇异点检测、轴速校核
- **不做**：不读 G 代码（吃 `MotionSegment`，吐关节值）；不碰几何内核；**不认识 `.ron`**

### `cncsim-config`
- **做**：解析 `.machine.ron`、语义校验（2 旋转 + 3 直线、限位不反向、`sign ∈ {±1}`）、产出各层自己的类型
- **不做**：不做任何计算；不做默认值猜测（缺参数就报错，不"合理推断"）

**为什么它是独立 crate**：磁盘格式是**跨层**的——`chain` 归 `kin`，`parts` 归 `render`/`collide`，`motion` 归 `sim`。
让 `kin` 读整个文件，它就得知道 `Shape::Box` 和 `ColliderSpec::Derived`，L1 算法层被磁盘格式污染。
**只有 `config` 知道"文件长什么样"**，各领域 crate 只接收自己的类型。

**方向不能反**：`config → kin`，不是 `kin → config`。领域层永远不知道自己被序列化成了什么。

**v1 只解析运动学部分**，`parts` / `motion` 被 serde 静默忽略。这不是遗漏，是分层：
等 `render` / `collide` 有了 `Shape` / `ColliderSpec` 类型，再在 `config` 里补，各层代码不动。

**一条锁漂移的测试**：`kin::MachineTopology::ac_trunnion()` 是测试用的硬编码夹具（测试不该依赖文件 I/O），
`hardcoded_matches_file` 断言它与真实 `.ron` 逐字段一致。**两份数据会悄悄分家，只有测试能拦住。**

### `cncsim-gcode`
- **做**：词法、模态状态机、方言、`MotionProgram`
- **不做**：不做运动学（输出的块里是**位姿**，不是关节值）

> 这条边界很重要：`gcode` 若自己调 `kin` 做 RTCP，解析器就绑死在某台机床上。**RTCP 是 kin 的事，gcode 只负责把 B/C 和 X/Y/Z 原样交出去。**

### `cncsim-voxel`
- **做**：稀疏树、`SparseGrid`、解析扫掠 SDF、CSG、MC 提取、`MeshData` 输出、
  STL 解析与网格体素化（`stl` / `meshvol`——设计模型比对的设计场来源）
- **不做**：不做碰撞判定（只提供 `DistanceField` 实现）；不碰 Bevy

### `cncsim-collide`
- **做**：GJK、凸体、保守推进、episode 聚类、`DistanceField` trait
- **不做**：不拥有体素；不知道机床长什么样（吃 `Collider` 列表）

### `cncsim-sim`
- **做**：状态机、`PlaybackBuffer`、后台线程、诊断聚合、`SimReport`、
  解释器 issue 逐条进报告（Trust 打通）、设计模型比对（`compare`）、非线性误差汇总
- **不做**：不含任何算法细节；不做渲染；不做文件 I/O

### `cncsim-render` / `cncsim-ui`
- **做**：把 `sim` 的快照画出来、把用户操作变成 `sim` 命令
- **不做**：不做任何计算（颜色映射之外）

### `cncsim-app`
- **做**：装配、窗口、CLI、读写文件
- **不做**：不含业务逻辑

## 4. 数据流与所有权

```
.gcode 文件
   │ ① app 读文件（I/O 在 app，不在 gcode）
   ▼
&str ──gcode::parse()──▶ MotionProgram        【不可变，解析后不再改】
   │
   │ ② kin：按插补周期展开
   ▼
Vec<SimStep>（关节值 + 刀位 + 时间戳）        【不可变，一次算完】
   │
   │ ③ 后台线程：voxel 切削 + collide 判定（顺序固定：先切后撞）
   ▼
TileUpdate / CollisionEpisode                 【只增不改，走 channel】
   │
   │ ④ sim 聚合成 PlaybackBuffer + SimReport
   ▼
render 读快照 / ui 读报告                      【只读】
```

**所有权三条规则**：

1. **`MotionProgram` 和 `Vec<SimStep>` 是不可变的**——算完之后谁都能读，不需要锁。
2. **`SparseGrid` 只有一个所有者：后台线程**。其他任何地方都拿不到它，只能通过 `DistanceField` 的只读快照或 `TileUpdate` 看结果。
3. **跨线程只走 channel，不共享可变状态**。

第 2 条是低耦合的关键：**毛坯网格的所有权单一**，就不可能出现"渲染线程和碰撞线程看到不同版本"。

## 5. 线程模型

```
主线程（Bevy）
  ├─ 读 PlaybackBuffer → 更新 Transform / Mesh
  ├─ 跑 egui
  ├─ hmi.tick()：推进控制状态机、聚合报警
  └─ 把用户命令写进 cmd channel
        │
后台仿真线程（独占 SparseGrid）
  ├─ 从 cmd 取命令
  ├─ 按 SimStep 顺序：voxel.cut() → collide.check()
  ├─ 产出 TileUpdate → tile channel（容量 64，满了阻塞＝天然限速）
  └─ 产出 CollisionEpisode → diag channel
```

**`voxel` 与 `collide` 都在同一个线程**，因为它们访问同一份 `SparseGrid`。放两个线程就要加锁，锁又带来顺序不确定性——**宁可串行**（碰撞开销远小于去除，见 ADR-004 §8）。

## 6. 错误与诊断的归属

| 层 | 错误类型 | 谁处理 |
|---|---|---|
| `gcode` | `ParseIssue`（行号 + 原因），**不中断** | `sim` 收进报告，UI 高亮行 |
| `kin` | `KinFinding`（奇异、超限、进给偏差） | `sim` 收进报告 |
| `voxel` | `VoxelError`（内存不足、h 非法） | 致命，返回 `sim` 后转 Error 态 |
| `collide` | `CollisionEpisode`（不是错误，是结果） | `sim` 聚类进报告 |
| `app` | I/O 错误 | 弹窗 |

**约定：解析失败不中断**。G 代码方言差异大，一行不认识就整份失败会让工具不可用——跳过该块、记录、继续。

## 7. 为什么不用 god `core`

把"公共类型"抽成一个 crate 看起来整洁，实际代价：

| 代价 | 说明 |
|---|---|
| **内聚度为零** | `core` 里的类型彼此无关，改 A 的动机和改 B 的动机不同 |
| **扇入爆炸** | 所有 crate 依赖它 → 改一行全项目重编译 |
| **变成垃圾桶** | 下一个"两个 crate 都要用"的类型还会往里塞，因为它已经在那儿了 |
| **掩盖设计问题** | 两个 crate 需要同一类型，本该问"它们是不是该共享一个概念"，`core` 让这个问题消失 |

**替代做法**：按概念簇拆。本项目恰好有三个清晰的簇——数学、运动、刀具。三个都小、都稳定、都有明确归属。

如果将来出现第四个跨 crate 概念，先问："它是不是某个现有簇的成员？"答不出来，再考虑新 crate——但**不要叫 `core`**，要用概念命名。

## 8. 反模式清单（写代码时对照）

| 反模式 | 症状 | 正确做法 |
|---|---|---|
| `core` 垃圾场 | 新建 `utils` / `common` / `types` crate | 按概念簇归属 |
| 循环依赖 | `kin` 里 `use voxel` | 由 `sim` 编排 |
| 解析器懂运动学 | `gcode` 里调 `kin::inverse` | 输出位姿，RTCP 归 `kin` |
| 渲染层算东西 | `render` 里做几何计算 | 算在 `voxel`，`render` 只上传 |
| 共享可变状态 | `Arc<Mutex<SparseGrid>>` | 单一所有者 + channel |
| 底层共享枚举 | `enum Diagnostic` 放在 `math` | 各层自带 finding，`sim` 组合 |
| `Pose` 约定漂移 | 各处自己定 axis 方向 | `motion` 里一种约定 + 测试锁 |

## 9. 自动化守卫

`tools/check_deps.py`：读每个 crate 的 `Cargo.toml`，逐条核对白名单，并额外检查两条：

1. **L0–L3 不得出现 `bevy` 依赖**（除 `render` / `ui` / `app`）
2. **不得存在 `cncsim-core` / `cncsim-common` / `cncsim-utils`** 这类名字

```bash
python tools/check_deps.py          # 违规则退出码 1
```

架构约束写在文档里会腐化，**只有写进 CI 才有效**。

## 10. 与 ADR-003 的一处修正

ADR-003 原计划"第一步借 cutrail 当运行时脚手架，用 `RemovalEngine` trait 隔离"。按本架构改为：

- **删掉 `RemovalEngine` trait**——它是为"运行时切换内核"设计的，而我们最终只用自研内核。
- **cutrail 降级为 `dev-dependency`**，放进 `cncsim-voxel/tests/` 当**测试预言机**（对拍体积与包围盒，容差 1%）。

好处：少一层间接、少一个 trait、`sim` 不需要知道"引擎可换"。而 ADR-003 想要的两件事——"有对照"和"不阻塞开发"——用测试依赖同样能得到，且不污染运行时。

## 11. 落地顺序

| 步 | 内容 | 为什么先做它 |
|---|---|---|
| 1 | `math` + `motion` + `tool`（三个词汇 crate） | 无依赖，先立地基 |
| 2 | `kin` + 三个锚点测试 | 风险最高，最早验证 |
| 3 | `tools/check_deps.py` + CI | **架构一立起来就上锁**，别等腐化 |
| 4 | `voxel`（自研；ADR-002 后不再引 cutrail，用解析 SDF / 暴力采样做 oracle） | 最重的一块 |
| 5 | `collide`（用半空间假实现单测） | 依赖 trait，可脱离 voxel |
| 6 | `sim` 编排 | 前面都通了才有意义 |
| 7 | `render` / `ui` / `app` | 最后 |

第 3 步的位置是刻意的：**架构守卫要在只有 3 个 crate 的时候上线**，那时违规成本最低；等到 11 个 crate 再上，改起来就疼了。

> **落地状态**（2026-10-30）：1–6 全部完成（`render` 完成了缓冲层与自包含 HTML 预览，
