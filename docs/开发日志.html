方案与 ADR

产出 核心判断
技术方案-五轴CNC仿真.md（~900 行） "先算后播"而非实时；五轴特有三角（非线性误差 / 轴速降额 / 奇异点）做成一等公民

核实到的关键事实：Bevy 0.20.0（2026-10-08）、bevy_egui 0.43.x 对应 0.20、0.20 起自定义着色器必须 WESL、PanOrbitCamera feature 默认关闭。 cutrail 0.1.1（纯 Rust 网格布尔）实测 2–6 ms/段、内存 92 MB——调研过，最终弃用。

两次"用户一句话推翻结论"：

  1. "纯自用" → 范围 60 → 40 人日。关键法理点：GPLv2 义务在"分发"时触发，私有使用不触发；但版权与分发是两回事，GrabCAD 的"非商用"限制的是使用场景。
  2. "sdf 精度 0.1mm" → 直接戳破 ADR-004 的"0.6 µm 必定检出"。我错在用均匀分布假设推"保证"——最坏情况下毛坯表面正好卡在两个体素层正中间，穿透薄片 ε < h/2 时一个体素中心都不在里面。 修正后：方向 A（毛坯体素 → 刀柄 SDF）严格保证只有 h/2 = 0.05 mm；方向 B（刀柄表面 → 毛坯 SDF）0.17 µm。 为什么差三个数量级：穿透区在毛坯体素格上是三维薄片（要 ε > h），在刀柄表面上却是二维补丁（周向宽 2√(2Rε)，只需 ε > δ²/(2R)）。

顺带修掉一个真漏洞：revbody_vs_stock 用 let Some(Band) = ... else { continue }，把 Full brick 一起跳过了 → 刀杆斜插实体区时整段漏报。

碰撞的成本控制：整根刀柄表面 δ=0.1 时约 94 万点，不可接受。按 brick 裁剪——只在与 Band brick 相交的那部分表面上生成采样点，实际接触面积通常 <200 mm² → 2 万点。

机床建模

核心洞察：摇篮式的运动学只有一个几何参数 L。 常被当参数的"H（Z 参考面 → A 轴中心）"不影响刀尖相对工件的位姿——把 Z=0 定在 A 轴中心就吸收了。

查出两个错误（手算锚点与程序对不上才暴露）：

  1. RTCP 写成 (z−L)，应为 (z+L) → Z 整体偏 360 mm，画面完全正常。
  2. n_W 的 Y 分量写成 −sinA·cosC，应为 +sinA·cosC。

教训：手推公式后必须用独立实现（齐次矩阵连乘）跑锚点。

golden 基准的诚实性：543 行里前 3 行是真 oracle（手推 + 独立矩阵双确认），后 540 行只是回归锁。

加工包络：A=0 → 340、A=30 → 420（峰值）、A=90 → 只剩 120。A=90 时瓶颈是 Y 不是 Z。

tip_w 约定坑：我最初写 tip_w = −Rᵀ·t，A=0 算出 300（应 340）、A=45 算出 0。查 verify_trunnion.py 才发现它用 tip = t[:3,3]——因为 RON 里旋转轴 sign = −1，链乘积实际是「刀具 → 工件」的变换，不是文档写的"工件 → 刀具"。

i8 精度口径修正

用户问"i8 能表示多少的精度"，算的时候发现文档只算了量化，漏了三线性重建——后者在曲面上比量化还大。

三个结论（详见项目记忆 §4）：φ0.5 球刀精加工面是 6.6 µm 不是 1.6 µm；"h 减半精度翻四倍"是错的（量化主导时只按 h 线性）；设计规则 h ≤ 0.11·√R_c。

教训：给"保证"必须列全误差项。只算一项就宣布下限，等于按最乐观的那一项承诺。

对拍抓到三个真问题（详见项目记忆 §7.4）：OpenVDB 基准的刀具体是空心的；它的毛坯窄带不完整；我们的 fill_box 不写精确边界 SDF，左侧壁偏 25 µm。

采样陷阱：不要用 11.0 + i*0.1 生成坐标再 floor(x/h)——18.9/0.1 = 188.9999，会掉到前一个体素，两边偏法还不一样。改成直接按体素索引采样。 测试设计：过零点用二分，且方向无关（左壁"材料→空气"、右壁"空气→材料"，写死 f(lo)<0 && f(hi)>0 会挂）。

精度上限实测（395 绿）

测试踩的坑：第一版把槽底放在 13.5h——那正好是体素中心，插值不需要跨格点，误差测出来全是 0.000 µm（假象）。改成 13.3h（体素中心之间）才暴露量化误差。

铣光大场景（395 绿）

50×50×100 / 200 刀 / h=0.2。一开始我们输 3×（10.6 vs 3.59 ms/刀），靠三项追平：

  1. prune_touched（10.3 → 3.4 ms）：prune() 每刀全量——15 块 × 4096 叶 × 512 体素 ≈ 3100 万次/刀。改成只折叠真正写过的叶。
  2. leaf_or_tile（2.3 → 2.1 ms）：一进叶就拿到 LeafView，512 体素直读；整叶同值且在带外时整叶跳过。
  3. fill_box_exact 走 set_cached_in_bounds（建场 240 → 147 ms）。

叶级剔除没效果：铣光的 AABB 本来就很紧（56.8×6.8×5.8），没有"远处叶"可剔。

用户洞察：接触面小 → 叶级整块写回（395 绿）

用户提「刀具每次与毛坯接触的部分很小，能否提高 cache 命中率」。

实测结论：这个场景不成立。 铣光每刀切 5 mm 深 × 6 mm 宽 × 56 mm 长，体积 1680 mm³ ÷ h³ = 21 万体素，与实测改动 23 万对得上——没有"算了白算"的余地。 浪费在改动的表达方式：散点 ([i32;3], i8) = 16 字节/条 × 23 万 = 3.4 MB 中转缓冲，超 L2 → 同一工作集被扫两遍。

改成整叶 512 值带回 + 一次 copy_from_slice：铣光 687 → 601 ms（−12.5%）。 空刀退化 0.56 → 1.28 ms：整块路径要先把 512 值搬进缓冲，而空刀一个都不改。真实加工里空刀走快移不进 cut_segment，不修。

必须配合的改动：z 分片要按叶层切，不能按体素层。按体素层切 48 片时每片不足一个叶层，每个叶都被裁成残块，整块路径一次都走不到（实测 整块 0 叶 / 散点 21 万条）。

试过但更慢（记下来免得重犯）：Option<Box<[S;512]>> 延迟分配 → 空刀 2.2 → 5.3 ns（编译器无法把判断提出循环）；blit_leaf 里对 512 值两次 fold 求最小幅值 → 3.43 → 3.81 ms（挪进求值循环后消失）。

顺带修掉真 bug：SparseGrid::leaf_slot 收叶坐标，却把 root_coord/l1_coord/l1_slot(leaf_coord(..)) 全按体素索引算了一遍——坐标一大就定位到错的槽。小域里偏移恰好为 0 所以一直没暴露。

多线程利用率 4.8× → 5.6×（395 绿）

先量后改：CNCSIM_THREADS 扫伸展性，24 线程只有 4.8×。两个根因，都是"看起来并行、实际不并行"：

  1. 分片轴选错：z 方向只有 5 个叶层，片数被 clamp 到 5，24 线程只有 5 个在跑。改成选叶层最多的轴（铣光 x 方向 36 个叶层）。
  2. 每叶一次 malloc：一刀 3920 次分配，24 线程并发打到同一把分配器锁上，加速比卡在 4.8×。改成 arena（所有叶的 512 值平铺 + offset 索引），LeafBlock 从 528 字节缩到 24 字节。

结果：20 mm 一刀 2.57 → 0.97 ms；铣光 601 → 434 ms；累计对初版 12.3×。 为什么是 5.6× 不是 24×：8 线程全 P 核时 5.2×，已贴近 8 物理核上限；E 核频率低一半，16 线程反而略慢。

bench 也修了：不能预热同一刀——预热会让第二遍变成"重复切"，遍历数掉三成、数字虚高（0.44 vs 实际 0.97）。

沿单轴走刀的截面共享（396 绿）

数学依据：立铣刀正交直刀 + 刀轴竖直时，dz 只依赖 z、dr 是到走刀线段的距离——叶完全落在走刀段内时 dr 退化成 |py|，SDF 与走刀方向的那个坐标完全无关。512 次求值 → 64 次（8×8 截面）。

条件保守：刀轴竖直且两端一致、位移只沿一个轴、不是沿 z（钻孔的扫掠体沿刀轴延伸）、叶整个在段内。

收益：铣光 434 → 371 ms（−15%）。 为什么不是 8×：sd_sweep 只占串行开销约 26%，共享最多省 26% × 7/8 ≈ 23%，实测 15%。

correctness 锁：axis_sharing_matches_general_path——同一条扫掠线一次切完 vs 拆成五段，逐位相同（抽查 1.4 万体素）。

① 表面行判据整数化 —— 会破坏逐位一致性

原判据 (cur as f64) * k_dist < neg_sd，看起来可以等价换成 cur < ceil(neg_sd * k_value)（因为 k_dist · k_value = 1）。

根因：LOD 取色按"格角"而不是"顶点"

LOD 顶点取切割色时查的是格的最小角 [p*k]。但：

  • 格边长 k·h（k=3 → 0.3 mm），面可能落在格的远端，最小角离它最远 0.3 mm；
  • 溯源子块只有 sub·h（sub=4 → 0.2 mm），盖不到 → 查到 0（毛坯灰）。

地平面恰好凑巧（面落在最小角所在的子块里），所以只有竖直面暴露问题—— 这也是为什么之前一直在看顶面、一直没发现。

let v = self.to_voxel_space(pos);

三口径 + 刀径：把"过切 6.4%"查清（11-06 晚）

五轴曲面法向点铣：叶轮 61.7% → 78.8%（11-07）

§40 的结论是"叶轮要五轴侧刃铣，本项目没有"。这一轮把那条结论改掉了一半： 不做侧刃铣（要直纹面），做法向点铣——刀轴沿设计面外法向，球贴上去切。

核心那一句

球头各向同性：球在 p 相切 ⟺ 球心在 p + R·n。而 球心 = tip + R·a，所以

tip = p + R·(n − a)              a = 刀轴

刀轴是自由的。a = n 时 tip = p；法向超出行程（叶片下表面 A=180°， 机床 110°）就把 a 拉到 110°，球照样相切，只是刀尖偏出去 R(n−a)。 叶轮 1 有 45% 的残料点栽在 A 超程上，改这一条之后是 0 个。
