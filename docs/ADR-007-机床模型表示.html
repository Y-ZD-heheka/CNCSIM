ADR-007 机床模型的表示

三表示一份真相源精细模型导入11 人日2026-10-28

状态：设计 日期：2026-10-28 关联：主方案 §4.1、§6.7；ADR-004 §1.1

0. 结论

"机床模型"其实是三个不同的东西，必须分开表示，但只允许有一份真相源。

表示 回答什么问题 精度要求 数据来源
运动学链 Vec<Joint> 各轴转到这个值，刀具在哪、朝哪 f64 精确（摆长错 0.1 mm 全盘错） 机床手册 / 实测
显示外形 Part::shape 屏幕上长什么样 厘米级，能认出来就行 由链生成，或挂 glTF
碰撞代理 Collider 会不会撞 保守（可大不可小） 默认从外形 AABB 派生

唯一的真相源是运动学链。显示外形和碰撞代理都挂在关节上、用关节索引关联，各自不存世界变换——所以它们永远跟着关节动，不可能与运动学脱节。

这条规则的价值在于消灭一整类 bug：外观显示"刀柄离工件还有 5 mm"而碰撞说"撞了"，或者反过来。只要三者共用一条链、一套偏移，这类矛盾从结构上就不存在。

要精细模型时，用 §8 的导入管线：glTF 节点树 → 关节分配 → rest-pose 局部变换 → 聚类碰撞代理 → 生成 RON。但 pivot 能不能自动提取取决于源文件有没有装配信息（STEP AP242 有，平铺 STL 没有），没有就必须打表量——给错的 pivot 比让人手填更危险。

1. 为什么不能合并成一种表示

三个诱人但错误的简化：

简化 后果
用显示网格做碰撞 几千三角面的网格布尔/距离查询，慢一个量级；而且美术做的薄壳在碰撞里是"实体"，会漏报
用碰撞盒子做显示 一台由十几个方块组成的机床——v1 可以接受，v2 用户会嫌丑
从下载的 CAD 模型反推运动学 最危险。pivot 交点、摆长、轴正向都推不出来，或推出来差几毫米；错了以后画面完全正常

第三条是 §6.7 已经论证过的：模型给几何，不给运动学。所以运动学必须手写，几何可以后补。

2. 单一声明与派生

pub struct Joint {
    // —— 运动学（ADR-002 §4.1） ——
    pub name: String,
    pub kind: JointKind,
    pub offset: DVec3,          // 相对父关节的固定偏置（装配尺寸）
    pub pivot: DVec3,           // 回转中心
    pub sign: f64,
    pub limit: (f64, f64),

    // —— 几何（本 ADR 新增） ——
    pub parts: Vec<Part>,
}

pub struct Part {
    pub shape: Shape,
    pub local: DMat4,           // 相对该关节的位姿（通常只有平移）
    pub color: [f32; 3],        // 缺省按轴着色
    pub collider: ColliderSpec,
}

pub enum Shape {
    Box  { size: DVec3 },
    Cyl  { r: f64, h: f64 },
    /// 外部 glTF：只做装饰，节点变换必须归零
    Gltf { asset: String, node: String },
}

pub enum ColliderSpec {
    /// 默认：由 shape 的 AABB 生成 OBB，保证 ⊇ 外形
    Derived,
    /// 显式：用户给若干凸体（用于外形 AABB 过松的部件）
    Explicit(Vec<ConvexPrim>),
    /// 不参与碰撞（装饰件：手柄、铭牌、拖链）
    None,
}

派生规则：

fn build(&self) {
    for (ji, joint) in chain.iter().enumerate() {
        let joint_entity = spawn_joint_transform(joint);      // 运动学
        for part in &joint.parts {
            let visual = spawn_visual_mesh(part);             // 渲染
            commands.entity(joint_entity).add_child(visual);
            match part.collider {
                Derived => register_collider(obb_of(part.shape), ji),   // 碰撞
                Explicit(cs) => register_collider(cs, ji),
                None => {}
            }
        }
    }
}

三处 add_child 到同一个 joint_entity，所以三者在结构上绑死。关节一转，显示和碰撞代理一起转，不可能只转一个。

3. 碰撞代理必须"外接"

方向不能搞反：

做法 后果
外接（circumscribe） 永不漏报；可能误报（把空气当成实体）
内接（inscribe） 可能漏报——不可接受

因为"稍微有碰撞没发现会带来灾难性后果"（ADR-004 的验收前提），代理只能往大做。

但外接 OBB 对 L 形/异形件会松得离谱：一个 L 形立柱用一个 OBB 包住，会多出半个体积的空气，导致大量误报。

所以：每个部件给 3–6 个凸体，而不是一个。L 形用两个盒子拼，带圆鼻的主轴头用一个盒子 + 一个圆柱。

// 主轴头：盒体 + 前端圆柱鼻
collider: Explicit(vec![
    ConvexPrim::Obb { half: (120.0, 90.0, 100.0), local: Mat4::IDENTITY },
    ConvexPrim::Cyl { r: 60.0, h: 80.0, local: translate(0.0, 0.0, -140.0) },
])

校验：Explicit 的并集必须落在 shape 的 AABB 内（否则说明代理超出了真实几何，是错的），且体积不应远小于 AABB（否则可能覆盖不足）。两个条件都只报警告，不阻断——因为手工标注总有例外。

4. 部件清单与粒度

v1 只需要这些（约 6–8 个部件）：

部件 挂在哪 外形 碰撞
立柱 固定（无关节） Box OBB ×1–2
横梁 / 桥板 X 或 Y 关节 Box OBB ×1
Z 滑枕 Z 关节 Box（细长） OBB ×1
主轴头 最内层旋转关节 Box + Cyl OBB + Cyl
工作台 / 转台 转台关节 Cyl 或 Box OBB 或 Cyl ×1
桥板 / 摇篮 转台关节 Box OBB ×2
刀库 / 换刀臂 — v1 不做 None

防护罩、拖链、线缆一律 Collider::None——它们撞了也不停机，参与碰撞只会制造噪声。

5. 数据从哪来

参数 来源 注意
offset / pivot / 摆长 机床手册的装配图，或实测（打表） 必须实测核对，手册给的是名义值
行程 / 转角限位 手册 转角限位常被操作工改过，问一下
shape 尺寸 手册外形尺寸，或卷尺量 厘米级够用
轴正向 手册 + 手动点动确认 Fanuc 与 Siemens 的 A 轴转向相反

不要做的事：从下载的 CAD 模型里"猜" pivot。网格里两个旋转体的公共轴线可以拟合出来，但精度和工时都不划算，而且错了极难发现。

一个可执行的校准流程（1 小时）：

  1. 在机床上装一根标准刀，主轴端面贴一张纸，Z 到 0，记录机械坐标。
  2. 手动转 A 到 +90°，用千分表找刀尖最低点，记录机械坐标 → 两次的差值就是摆长。
  3. 把这些数填进 RON，用仿真的"单轴点动"模式核对：屏幕上刀尖的位置应与实测一致（±0.1 mm）。

第 3 步就是验收——如果仿真里的刀尖位置和实测对不上，运动学参数就是错的，不用等到撞刀才发现。

6. 一致性测试

#[test]
fn every_part_follows_its_joint() {
    // 转动 C 轴 90° → 挂在 C 上的部件世界变换必须跟着转 90°
    // 挂在父关节上的部件不动
    let before = world_xform(&app, spindle_head);
    set_joint(&mut app, "C", 90.0);
    let after = world_xform(&app, spindle_head);
    assert!((after.rotation * Vec3::Z).angle_between(before.rotation * Vec3::Z) - PI/2.0).abs() < 1e-6);
}

#[test]
fn derived_collider_encloses_visual() {
    // Derived 的代理 AABB 必须包含外形 AABB
    for part in all_parts() {
        if matches!(part.collider, ColliderSpec::Derived) {
            assert!(part.collider_aabb().contains(part.visual_aabb()));
        }
    }
}

#[test]
fn explicit_collider_within_visual() {
    // Explicit 的并集不能超出外形 AABB（超了说明代理写错了）
    for part in all_parts() {
        if let ColliderSpec::Explicit(cs) = &part.collider {
            assert!(part.visual_aabb().contains(union_aabb(cs)));
        }
    }
}

第一条最重要：它锁住"三者挂在同一个关节上"这个结构约束。写错成挂在世界坐标上，画面静止时完全正常，一动就露馅——而这正是"摆长错 50 mm 但画面正常"那类 bug 的另一种形态。

8. 从精细模型生成描述代码（导入管线）

精细模型（CAD/glTF）和我们的 Part 描述之间隔着一个转换。这一节给出可执行的管线。

8.1 先判断：你的模型有多少"装配信息"

能自动化到什么程度，完全取决于输入源里有没有关节定义——不是几何精度。

输入源 装配信息 pivot 能提取吗 需要人工做的事
STEP AP242（含 kinematics） ✅ kinematic_link / kinematic_pair 可以，轴和限位都在 核对数值
CAD 原生（Fusion / SW / FreeCAD，带装配约束） ✅ 配合/旋转副 可以 核对数值
STEP AP203 / AP214 只有装配树，无运动副 ❌ 手填 pivot + 摆长
glTF（按关节建节点） ⚠️ 隐含在节点变换里 ⚠️ 节点原点恰在轴上才行 手填 + 核对
STL / OBJ / 平铺 glTF dump ❌ ❌ 全部手填

结论：如果手上是平铺网格，导入工具只能帮你算局部变换和碰撞代理，运动学参数还是得打表量（§5）。

这一条必须先确认，否则会做出一个"看起来很智能但给不出正确 pivot"的工具。给错的 pivot 比让人手填更危险——手填时人会去量，自动生成的数值人不会怀疑。

8.2 管线

精细模型（glTF / STEP→glTF）
   │
   ├─① 解析节点树，取每个 mesh 的世界变换 M_world
   │
   ├─② 分配关节：mesh → joint_index        （§8.3）
   │
   ├─③ 算 rest-pose 局部变换                （§8.4 陷阱）
   │     local = inv(M_joint_world) · M_world
   │
   ├─④ 生成碰撞代理：AABB 聚类合并          （§8.5）
   │
   └─⑤ 输出 .machine.ron + 引用 glTF 节点名

做成子命令：

cncsim-import machine.glb --map joints.yaml --rest-pose --out machines/ac_head.machine.ron

8.3 关节分配：命名约定 > 交互式 > 自动推断

不要做自动推断。从几何判断"这个网格属于哪个关节"是不可靠的——相邻部件在几何上是连续的，没有可判别的边界。

用一张映射表（YAML），一次写好后可复用：

# joints.yaml
joints:
  X:   [ram_x, table_x_slide]
  Y:   [saddle_y]
  Z:   [z_slide, spindle_mount, z_bellows]
  C:   [c_housing, c_rotor, c_cover]
  A:   [a_trunnion, a_plate, a_clamp]
fixed: [column, base, enclosure]      # 不挂任何关节
skip:  [cable_chain, labels, screws]  # 不导入

配套一个小工具：cncsim-import --list-nodes 打印节点树 + 每个节点的 AABB，方便对着填。

如果模型命名很乱，做一个交互式分配器（3 人日）：在 Bevy 里点选网格 → 按快捷键 1–5 分配给 XYZAC。这个比自动推断靠谱得多，而且只做一次。

8.4 rest pose 陷阱

local = inv(M_joint_world) · M_world 里的 M_joint_world 必须是全轴归零时的关节世界变换。

如果模型是在某个非零位姿下导出的（比如 C 转了 30°），算出来的 local 会把这个 30° 固化进去——之后 C 轴转到 30° 时，部件会显示在 60°。

处理： - 导出前把所有轴回零（推荐）。 - 或者导入时把模型摆回零位再算（工具提供 --zero-pose 选项，逐轴把关节变换的逆乘回去）。

验证方法：导入后把 C 轴从 0 转到 90°，看部件是否绕着正确的那根轴转。转的轴错了或位置错了，就是 rest pose 没处理对。

8.5 碰撞代理：AABB 聚类合并

一个关节可能有几十个 leaf mesh（主轴头总成往往 50+ 个零件）。逐个生成 OBB 会让碰撞对数量爆炸。

/// 把同一关节的 mesh 合并成 ≤ max_parts 个 OBB
fn cluster_colliders(meshes: &[MeshAabb], max_parts: usize) -> Vec<Obb> {
    if meshes.len() <= max_parts {
        return meshes.iter().map(|m| Obb::from_aabb(m.aabb)).collect();
    }
    // 沿最长轴二分，递归到 ≤ max_parts 个簇
    // 每个簇取所有 mesh 的并集 AABB → 一个 OBB
    // 代价：外接更松，但数量可控
    split_longest_axis(meshes, max_parts)
}

目标：每个关节 ≤6 个 OBB。实测主轴头这类总成，6 个 OBB 的松紧度可以接受（多出 10–20% 体积的空气，对应少量误报）。

注意：聚类在关节局部坐标系里做，否则关节一转，OBB 就偏了。

local 用 4×4 矩阵行优先 16 个数——比 (translate, rot, scale) 三元组少一层歧义，且能表达任意装配偏移。

8.7 精细模型的渲染代价与应对

项 数值 说明
整机三角面 200 万以内 静态网格，每帧成本只与三角面有关，与文件大小无关
文件大小 50–300 MB 用 meshopt / Draco 压缩，加载时解压
显存 200 万面 × ~40 B ≈ 80 MB 加贴图后 200–400 MB
加载时间 2–8 s 可接受；做成后台加载 + 进度条

三个必须做的可用性处理：

  1. 显示模式：整机 / 半透明机床 / 仅工作区 / 隐藏。精细模型会挡住工件，这是必然的——不做这个开关，用户会关掉整个机床显示。
  2. 剖切时自动半透明：进剖切模式时把不参与碰撞的装饰件（罩壳、拖链）降到 10% 不透明度。
  3. 材质隔离：机床用 StandardMaterial，不参与 ADR-005 的切割面着色——否则调色板索引会被套到机床上。

尺寸不准的模型怎么用：下载来的模型常是"示意"比例，尺寸与真机不符。此时不要把 collider 设成 Derived——那会让碰撞检测去测一个假机床。改用 Explicit 手填实测尺寸的 OBB，模型退化为纯装饰。这正是 §1 把"显示外形"和"碰撞代理"分开的用处：观感可以妥协，正确性不行。

项 人日

映射表 + rest-pose 局部变换计算 1.5

8.9 一个反直觉的建议

先用方块跑通全流程，再上精细模型。

理由：精细模型会掩盖运动学错误。方块机床转错了轴，一眼就能看出来；真实模型转错了，可能只是"某块钣金穿模了"，很容易被当成美术问题忽略。

顺序应该是：

  1. 方块模型 + 实测参数 → 验证运动学（§6 的一致性测试全绿）
  2. 换上精细模型 → 只替换 Shape，运动学一行不动
  3. 对比两次的刀尖轨迹 → 必须完全一致（1e-9）

第 3 步是一次免费的回归测试：如果换模型后轨迹变了，说明导入过程动了本不该动的东西（多半是 rest pose）。

9. 一句话

运动学是真相，外形是投影，碰撞代理是保守的外包络。 三者挂在同一棵关节树上，各自不存世界变换——这样它们不可能互相说谎。
