## 0. 结论

三句话：

1. **不需要通用网格碰撞。** 因为毛坯是体素 SDF 不是网格、夹具与机床部件是凸体、刀具是旋转体——没有一对是"网格 vs 网格"。这砍掉了 BVH 动态重建这个最麻烦的部分。

2. **正确性风险不在算法，在时间采样。** 100 m/min 快移 = 1.67 mm/ms，2 mm 薄壁会被整步跳过。必须做**保守推进（conservative advancement）**，不能靠加密采样硬扛。

3. **可以完全复用材料去除的解析刀具 SDF**，而且碰撞判定是**精确的**（不是体素近似）：拿毛坯的窄带体素位置去测刀具解析 SDF 的符号。

工作量 **14 人日**（原估 12，增量在连续化与测试）。

## 1. 问题分解：谁和谁撞

### 1.1 对象分类

| 对象 | 几何表示 | 来源 |
|---|---|---|
| 切削刃部分（刀尖 → 刃长） | 旋转体 profile | 刀具定义 |
| 刀杆 + 刀柄 + 夹头 | 旋转体 profile（同一条母线） | 刀具定义 |
| 主轴头 / Z 滑枕 / 立柱 | OBB（参数化机床生成，§6.7） | 拓扑配置 |
| 工作台 / 转台 / 桥板 | OBB | 拓扑配置 |
| 毛坯 | 稀疏窄带 SDF | `cncsim-voxel` |
| 夹具 / 压板 | OBB（v1 只支持方块，不支持导入网格） | 用户输入 |

**关键观察**：v1 里没有三角形网格参与碰撞。毛坯是体素，其余是 OBB 或旋转体。

### 1.2 必须排除的"合法接触"

不做这一步，程序会疯狂误报：

| 合法接触 | 排除方法 |
|---|---|
| **切削刃 vs 毛坯** | 这是切削不是碰撞。只把 **刃长以上** 的 profile 段（刀杆+刀柄）拿去测毛坯 |
| 父子关节（Z 滑枕 vs 主轴头） | 拓扑链上距离 ≤ 1 的关节对跳过 |
| 相邻关节（C 轴 vs A 轴） | 距离 ≤ 2 的跳过 |
| 刀具 vs 主轴头 | 同一装配体，直接排除 |
| 毛坯 vs 工作台 | 毛坯本来就放在台面上，恒接触。改为只测"毛坯底面是否低于台面"这一条标量 |

第 5 条是最容易漏的：毛坯放在台面上，两者永远"相交"。正确做法是单独一条规则（毛坯 Z 下界 ≥ 台面 Z 上界），不进入通用碰撞流程。

### 1.3 需要检查的配对

```
刀杆/刀柄  ×  毛坯            ← 最常见、最危险（撞工件）
刀杆/刀柄  ×  夹具/压板
刀杆/刀柄  ×  工作台/转台
切削刃      ×  夹具/压板       ← 切到压板
主轴头      ×  毛坯            ← 五轴摆头时主轴头碰工件
主轴头      ×  转台/桥板
滑枕        ×  转台/桥板
毛坯        ×  夹具            ← 装夹干涉
```

约 20–50 对（取决于机床部件数量）。

## 2. 算法分层

```
① 粗筛：球/ AABB            每对每步，O(n²) 但 n≈50
      ↓ 通过（约 5%）
② 窄相：距离 / 相交
      ├─ 旋转体 × SDF    → 体素点 × 解析 SDF（精确）
      └─ 凸体 × 凸体      → GJK 距离
      ↓
③ 连续化：保守推进（只在②报"近"时触发）
```

### 2.1 粗筛：不需要 BVH

n ≈ 50 且大部分对象是静态的。50² / 2 = 1250 次 AABB 测试，每次约 20 flops → 25k flops/步。100k 步 = 2.5e9 flops ≈ 2 秒**总计**，可忽略。

**所以 v1 不要 BVH。** 这一条把工作量从"BVH + refit + 退化处理"降到"一个 AABB 数组"。如果将来夹具支持导入网格（几千个三角形），再加 BVH 也不迟。

> 学术界对五轴碰撞的经典做法是"包围球粗筛 + sweep plane 精筛"（见 §10 参考文献 [1][2]），其中包围球粗筛这一层与我们的 AABB 粗筛等价。他们的 sweep plane 是为了处理**带毛坯几何更新的全局碰撞**；我们因为毛坯已经是体素，直接查体素即可，不需要 sweep plane。

### 2.2 窄相 A：旋转体 × 毛坯（复用解析 SDF）

毛坯的窄带 SDF 存的是体素中心到毛坯表面的**有符号距离**；刀具的解析 SDF（ADR-002 §3.2 的 `sd_profile`）给出任意点到刀具实体的距离，**没有带宽限制**。

于是判定变成：**取与刀杆 AABB 相交的 brick 里的体素，逐点求 `sd_profile`，若存在 < 0 的点则碰撞。**

```rust
fn revbody_vs_stock(
    grid: &SparseGrid,
    revbody: &Profile,          // 只含刃长以上的段
    xform: &DMat4,              // 刀具位姿
    axis_samples: &[DVec3],     // 刀杆轴线代表点（世界系）
) -> Option<Collision> {
    let aabb = revbody.aabb(xform);
    let inv = xform.inverse();

    for brick_id in grid.bricks_overlapping(aabb) {
        match grid.bricks.get(&brick_id) {
            // 无材料。只去料不加料 → 永久安全，可跳过
            None | Some(BrickState::Empty) => continue,

            // 整块实心：刀杆深埋。用轴线代表点做包含测试
            Some(BrickState::Full) => {
                if axis_samples.iter().any(|p| grid.brick_contains(brick_id, *p)) {
                    return Some(Collision::deep(brick_id));
                }
            }

            // 表面穿过该块：逐体素精确判定（主力路径）
            Some(BrickState::Band(v)) => {
                for (i, &d) in v.iter().enumerate() {
                    // 只测带内体素；|d| == BAND 的钳制值直接跳过
                    if (d as f64).abs() >= BAND as f64 { continue; }
                    let p_local = inv.transform_point3(grid.voxel_center(brick_id, i));
                    if sd_profile(p_local, revbody) < 0.0 {
                        return Some(Collision::at(grid.voxel_center(brick_id, i)));
                    }
                }
            }
        }
    }
    None
}
```

**为什么这是精确的（修正上一版的说法）**：不是"体素近似"。毛坯 SDF 是**解析距离的 CSG 结果**——初始毛坯（方块/圆柱）SDF 精确，每次切削做 `max(d_stock, -d_sweep)`，而 `d_sweep` 由解析 `sd_profile` 沿段取最小值得到。所以**体素中心上的 SDF 值是到真实加工面的精确距离**，不是 h/2 的近似。

> 钳制安全性的证明：窄带把 |d| > band 的值钳到 ±band。对**减法** CSG，若真实值 d₀ > band 而存储值被钳为 band，则 `max(band, -d_sweep) = band` 与 `max(d₀, -d_sweep) = d₀` 同号且都满足 ≥ band——符号与"至少 band 远"这两个性质都不丢失。因为只去料不加料，钳制是安全的。

**唯一的误差来源是采样覆盖**（体素中心有没有落在穿透区内），不是距离精度。

**但覆盖保证只有 h/2 = 0.05 mm**：穿透区是厚度 ε 的三维薄片，若毛坯表面正好卡在两个体素层中间，ε < h/2 时一个体素中心都不在里面。所以**这条路径是兜底与定位，不是主力检出**。

主力检出改在**刀柄表面采样**（方向 B，§2.5.2）：同一个相交判定，采样域从"毛坯的体素格"换成"刀柄的表面"，穿透区从三维薄片变成二维补丁，采样密度阈值从 `h/2` 提升到 `δ²/(2R)` = 0.17 µm。

**但真正的瓶颈不是采样密度，是 `i8` 量化 + 三线性重建**：`sdf_stock(p)` 的符号可信度由两项决定——量化半档 1.58 µm（∝h）与重建 `h²/(8R_c)`（∝h²）。所以实际检出下限是**平面 1.6 µm、常规曲面 2.0 µm**。详见 §2.5.9。

两个方向都做：B 负责"绝不漏报"，A 负责"报出毛坯上哪个位置被撞了"。

**`Full` brick 的处理是上一版的漏洞**：原代码用 `let Some(Band) = ... else { continue }` 把 `Full` 一起跳过了。刀杆斜插进实体区域时，周围可能全是 `Full` brick、没有 `Band` brick 在附近，就会**整段漏报**。现在用轴线代表点做包含测试兜住。

> 这个兜底是**后盾而非主力**：由 §5.4 的重分类规则，表面只存在于 `Band` brick 中，`Full` brick 意味着所有体素都在表面内 ≥ band（0.4 mm）。所以任何真实碰撞必须先穿过 `Band` 外壳，在那里被逐体素路径捕获。`Full` 路径只负责"刀杆已深埋"这种极端情形。

**代价**：每个 Band brick 最多 4096 个体素，只有刀杆 AABB 覆盖的才遍历（通常 1–3 个）→ 约 1e4 次 `sd_profile`。刀杆贴近毛坯的时间占比 < 5%，总开销可忽略。

### 2.3 窄相 B：凸体 × 凸体（GJK，解析 support function）

涉及：OBB × OBB（机床自碰）、OBB × 旋转体（夹具 × 刀柄）。

旋转体做**精确**凸分解：母线 profile 在拐点处切成若干圆台/圆柱/球，每一段本身就是凸体，**不做多边形离散**（理由见 §2.6）。一个刀柄通常 3–6 段。

```rust
enum ConvexPart { Obb(Obb), Cylinder { r: f64, h: f64 }, Frustum { r0: f64, r1: f64, h: f64 }, Sphere { r: f64 } }

/// GJK 只需要支持映射，不需要顶点表
fn support(part: &ConvexPart, xform: &DMat4, dir: DVec3) -> DVec3;

fn gjk_distance(a: &ConvexPart, ta: &DMat4, b: &ConvexPart, tb: &DMat4) -> f64
```

**为什么用 GJK 而不是纯 SAT**：SAT 只给布尔相交，保守推进需要**距离**。GJK 同时给出两者。

**GJK 的退化陷阱**（必须写进代码注释）：

- 当两形状**恰好相切**时，单纯形可能退化（体积为零），方向向量求不出来 → 迭代震荡或返回错误距离。
- 处理：① 用 `margin` 把"相切"变成"明确分离"（所有查询加 0.1 mm 膨胀）；② 单纯形体积小于 1e-12 时提前返回 0；③ 迭代上限 32 次，超限返回上一次的下界。

> 这正是 ADR-003 §8 S2 说的"用保守距离代替精确接触流形"。**碰撞检测只需要回答"距离是否小于安全间隙"，不需要精确接触点。** 加 0.1 mm 膨胀后，所有退化情形都变成明确分离或明确相交，GJK 的数值问题消失。

### 2.4 为什么不用"点采样"做凸体 × 凸体

一个诱人但错误的简化：把 OBB 的 8 个角点拿去测旋转体 SDF。**会漏报**——旋转体可能穿过 OBB 的面而所有角点都在外面（细长刀柄斜穿大压板）。

所以凸体对凸体必须用 GJK，不能采样。

### 2.5 检出保证：0.1 mm 采样到底能保证什么（修正）

先纠正上一版的一个错误结论。上一版用"穿透区体积 / h³ ≥ 8"推出"0.6 µm 必定检出"——**这个推导用了均匀分布假设，而保证不能依赖分布**。真实的最坏情况差三个数量级。下面是正确版本。

#### 2.5.1 方向 A（毛坯体素 → 刀柄 SDF）的保证只有 h/2 = 0.05 mm

原方案的采样域是**毛坯的体素格**：遍历 Band brick 里的体素中心，测它是否落在刀柄内。

穿透区是夹在"毛坯表面"与"刀柄表面"之间的一层薄片，厚度就是穿透深度 ε。

最坏情况：毛坯表面（局部为平面）恰好落在两个体素层**正中间**。

```
体素层 z = 0.0    ← 深度 0.05 mm（在毛坯内）
         ↑ 毛坯表面 z = 0.05
         ↑ 刀柄侵入到 z = 0.05 + ε
体素层 z = 0.1    ← 深度 0.05 mm（在毛坯外）
```

若 ε < 0.05 mm，这层薄片里**一个体素中心都没有** → 完全漏报。

所以：

> **方向 A 的严格保证是 ε ≥ h/2 = 0.05 mm。**

0.05 mm 对"会不会撞"这个工程问题其实够用（真实碰撞都在 0.1 mm 以上），但**它撑不起"面片级"的说法**，也不能说成 µm。上一版的 µm 是错的。

#### 2.5.2 方向 B（刀柄表面 → 毛坯 SDF）：采样密度保证 0.17 µm

同一个相交判定，换一个采样域，结果完全不同。

相交的充要条件是"存在刀柄表面上的点落在毛坯内部"。所以直接**采样刀柄表面**：

```
对刀柄表面上的每个采样点 p（间距 δ）：
    若 sdf_stock(p) < 0  →  碰撞
```

为什么这一下就好三个数量级——因为穿透区在**刀柄表面上是二维补丁**，不是三维薄片：

- 圆柱（半径 R）侧面切入平面深度 ε，交线在圆柱面上形成一个补丁，周向宽度 `w = 2√(2Rε)`
- δ 间距的采样要漏掉它，必须 `w < δ`
- 反解：**`ε > δ² / (2R)`**

| δ | R | 最小可检出 ε |
|---|---|---|
| 0.1 mm | 30 mm | **0.17 µm**（这是**采样密度**，不是最终下限——符号可信度见 §2.5.9） |
| 0.1 mm | 15 mm | 0.33 µm |
| 0.1 mm | 5 mm | 1.0 µm |

**关键点**：这里的 0.1 mm 仍然是采样间距，但因为是二维采样，阈值按 `δ²` 而不是 `δ` 缩小。三维薄片只能靠 `ε > h`，二维补丁可以靠 `ε > δ²/(2R)`。

#### 2.5.3 为什么方向 B 不需要宽频带 SDF

方向 B 只问"这个点是否在毛坯内"，即 `sdf_stock(p) < 0`。窄带的 0.4 mm 完全够——**超出带宽的点被钳制成 +0.4，而它本来就远离表面、不可能碰撞，钳制方向正好是安全的**。

这是方向 B 的第二个优势：它不需要为了覆盖刀柄半径（30 mm）去加宽带宽（那会让内存 ×75）。

反观方向 A 如果要做到同样精度，就得让 band ≥ 刀柄半径，内存从 130 MB 涨到 9.75 GB——不可行。

#### 2.5.4 最终方案：两个方向都做

| 方向 | 作用 | 保证 | 成本 |
|---|---|---|---|
| **B（主）** 刀柄表面 → 毛坯 SDF | 主力检出 | **0.17–1 µm** | 采样点数 ∝ 接触面积/δ² |
| **A（辅）** 毛坯体素 → 刀柄 SDF | 兜底 + 提供接触位置 | 0.05 mm | 1e4 体素/次 |

A 保留的理由不是检出，是**定位**：碰撞点报在体素中心，比报在刀柄表面采样点上更贴近"毛坯上哪里被撞了"这个语义。而且 A 能在 B 的采样出现空洞时兜住。

#### 2.5.5 成本控制：按 brick 裁剪采样域

整根刀柄表面积 `2πRL`，δ=0.1 时约 94 万点，不可接受。裁剪办法：

```rust
// 只在与 Band brick 相交的那部分刀柄表面上生成采样点
for brick_id in grid.bricks_overlapping(holder_aabb) {
    let Some(BrickState::Band(_)) = grid.bricks.get(&brick_id) else { continue };
    let box_ws = grid.brick_aabb(brick_id).expand(BAND as f64 * grid.h);
    for p in sample_revbody_surface_in_box(&holder, &box_ws, DELTA) {
        if grid.sdf(p) < 0.0 { return Some(Collision::at(p)); }
    }
}
```

`sample_revbody_surface_in_box` 只需要在给定的 box 内生成圆柱面上的格点（角度区间 + 轴向区间求交），实现约 60 行。

实际接触面积通常 < 200 mm²，δ=0.1 时约 2 万点；首点命中即返回，平均远小于此。

#### 2.5.6 保证的边界（必须说清）

| 情形 | 保证 | 说明 |
|---|---|---|
| 刀柄侧面切入毛坯 | ✅ **0.17–1 µm** | 方向 B，§2.5.2 |
| 刀柄端面切入毛坯 | ✅ 更宽松 | 端面是平面，补丁面积 ∝ ε |
| 刀柄 vs 夹具/台面/机床 | ✅ **精确** | 解析 support function 的 GJK，零误差（§2.6） |
| 毛坯内部孔洞，刀柄穿过不碰壁 | ✅ 不误报 | 孔洞周围是 Band，采样点都在毛坯外 |
| **薄壁厚度 < 2h（0.2 mm）** | ⚠️ 几何本身失真 | 体素场无法分辨"薄壁"与"无壁"。要覆盖必须 h ≤ 0.05（内存 ×4） |
| 毛坯表面**曲率半径 < h** 的尖角 | ⚠️ 表面位置误差 ≤ h/2 | 方向 B 的采样点落在真实表面上，但 `sdf_stock` 在尖角附近受带宽插值影响 |

**薄壁那条是硬约束**，不是实现问题：0.1 mm 的体素场里，0.15 mm 的薄壁和 0.05 mm 的薄壁在数值上几乎无法区分。如果你的零件有 0.2 mm 以下的筋，现在就要把 h 定到 0.05。

#### 2.5.8 h 可调时的保证矩阵

h 不做成编译期常量，而是 `GridConfig { h: f64, band_voxels: u8 }`。**一个旋钮同时控制内存、速度和检出保证**，三者都是 h 的幂函数：

| 量 | 与 h 的关系 | 说明 |
|---|---|---|
| 窄带内存 | **∝ 1/h²** | `mem ≈ 8.25 · A / h²`（8³ 叶，见 ADR-006 §4） |
| 单段去除耗时 | **∝ 1/h²** | 带宽固定 4 体素，只随面积变 |
| 方向 A 采样保证 | **∝ h**（h/2） | 三维薄片，卡在两个体素层之间 |
| 方向 B 采样保证 | **∝ h²**（`h²/8R_c`；平面精确） | 二维补丁，δ 取 h |
| **`i8` 量化** | **∝ h**（`band·h/254`） | 带宽随 h 缩放，档距跟着缩放 |

**注意：采样间距 δ 取 h，采样项按 h² 改善——但最终总误差不是 h²。**

| h | 内存 | 单段耗时 | 方向 A 采样 | 方向 B 采样（平面 R=30） | 方向 B 采样（曲面 R_c=3） |
|---|---|---|---|---|---|
| 0.2 mm | 52 MB | ~0.02 ms | 0.1 mm | 0.67 µm | 1.7 µm |
| **0.1 mm** | **206 MB** | **~0.06 ms** | **0.05 mm** | 0.17 µm | 0.42 µm |
| 0.05 mm | 825 MB | ~0.25 ms | 0.025 mm | 0.042 µm | 0.10 µm |
| 0.025 mm | 3.3 GB | ~1.0 ms | 0.0125 mm | 0.011 µm | 0.026 µm |

**采样密度不是最终保证，还要加量化（∝h）。合计（取最坏同号）：**

| h | `i8` 量化半档 | **方向 B 平面 合计** | **方向 B 曲面 R_c=3 合计** | 主导项 |
|---|---|---|---|---|
| 0.2 mm | 3.15 µm | **3.2 µm** | **4.8 µm** | 量化 |
| **0.1 mm** | **1.58 µm** | **1.6 µm** | **2.0 µm** | 量化 |
| 0.05 mm | 0.79 µm | **0.79 µm** | **0.89 µm** | 量化 |
| 0.025 mm | 0.39 µm | **0.39 µm** | **0.42 µm** | 量化 |

**这张表推翻了"h 减半精度翻四倍"的说法**：h ≤ 0.1 时量化项主导，**总误差只按 h 线性改善**——h 减半、内存 4 倍，误差只降一半。想要 h² 的收益必须同时换 `i16` 把量化项压下去。

**曲面那一列为什么更差**：`sdf_stock(p)` 由三线性插值得到，平面上插值精确，曲面上误差 ~`h²/(8R_c)`。所以曲面区域的采样保证取 `max(h²/2R, h²/8R_c)`——曲率半径越小，越受插值限制。

**三个预设**（UI 上显示预估内存与保证，让用户自己权衡）：

| 预设 | h | 用途 | 不适合 |
|---|---|---|---|
| 快速检查 | 0.2 mm | 验证会不会撞、刀路有没有明显错误 | 出报告；薄壁件 |
| **标准** | **0.1 mm** | 日常验证，过切/残留报告 | 0.2 mm 以下的筋 |
| 精密 | 0.05 mm | 薄壁件、高价值件、正式报告 | 2 小时以上的长程序（算得慢） |

**自动反推**：用户给内存上限，程序算 h 并回显保证：

```rust
fn auto_h(area: f64, mem_budget: usize) -> f64 {
    // mem ≈ 8.25 · A / h²（8³ 叶的实测系数，见 ADR-006 §4）
    //   →  h = sqrt(8.25 · A / mem)
    ((8.25 * area / mem_budget as f64).sqrt()).clamp(0.02, 0.5)
}
```

例：A=2.5×10⁵ mm²、预算 500 MB → h ≈ 0.064 mm。

**两条约束必须说清**：

1. **h 是加载期参数，不是运行中可拖的滑块。** 改 h 要重建整个体素场（重新切削），代价等于一次完整仿真。UI 上做成"下次仿真生效"。
2. **可调不等于可以规避薄壁问题。** 零件若有 0.2 mm 以下的筋，就必须选 h ≤ 0.05；可调只是让你**按任务选**，不是让粗网格也能覆盖细特征。

#### 2.5.9 真正的瓶颈：`i8` 量化 + 三线性重建（1.6 / 2.0 µm）

§2.5.2 算出 0.17 µm，那是**采样密度**的限制。但方向 B 的判定是 `sdf_stock(p) < 0`，而 `sdf_stock(p)` 由 `i8` 体素值三线性插值得到——所以有**两项**误差：

```
① 量化        band = 4 体素 × h=0.1 mm = ±0.4 mm
              分档 ±127 → 每档 3.15 µm → 半档 1.58 µm        （∝ h）
② 三线性重建  h²/(8·R_c)，平面上为 0                            （∝ h²）
```

**穿透 0.5 µm 时，插值出来的值可能是 +1 µm，判为"没碰到"。** 所以采样再密也没用——**符号本身的置信度由这两项决定**。

| 限制来源 | 数值 | 是否瓶颈 |
|---|---|---|
| 采样密度 `δ²/(2R)` | 0.17 µm | 否 |
| **`i8` 量化半档** | **1.58 µm** | **是（平面）** |
| **三线性重建** `h²/(8R_c)` | **0.42 µm**（R_c=3） | **是（曲面）** |

| 曲面曲率半径 | 量化 | 重建 | **合计** |
|---|---|---|---|
| 平面（∞） | 1.58 µm | 0 | **1.6 µm** |
| 10 mm | 1.58 µm | 0.13 µm | 1.7 µm |
| **3 mm**（φ6 球刀） | 1.58 µm | 0.42 µm | **2.0 µm** |
| 1 mm | 1.58 µm | 1.25 µm | 2.8 µm |
| **0.25 mm**（φ0.5 球刀） | 1.58 µm | 5.00 µm | **6.6 µm** |

**最终口径（三项分档，不是一个数）**：

- **平面 → 穿透超过 1.6 µm 必定检出**
- **曲面 R_c ≥ 0.8 mm → 2.0 µm**（h=0.1 时插值项不超过量化项的临界曲率是 0.79 mm）
- **R_c < 0.8 mm → 1.6 + h²/(8R_c)**，φ0.5 球刀精加工面是 6.6 µm

**第三条最容易被忽略**：小刀具精加工面的瓶颈不是 `i8`，是**网格太粗**。承诺"1.6 µm"对 φ0.5 球刀面差了 4 倍。

**设计规则**：要插值项不超过量化项，取 `h ≤ 0.11·√R_c`（mm）。R_c=3 → h ≤ 0.19；R_c=0.25 → h ≤ 0.056。
反解"总误差 ≤ ε"：`h ≤ min(254·ε/band_voxels, √(8·R_c·ε))`。ε=2 µm、R_c=3 → h ≤ 0.127（h=0.1 够）；ε=1 µm → h ≤ 0.064（必须降到 0.05）。

### 想提精度就换 `i16`，不是换 f64

| 方案 | 每档 | 内存（h=0.1） | 相对 |
|---|---|---|---|
| **i8, band=4（默认）** | 3.15 µm | **206 MB** | 1× |
| **i16, band=4** | **12.2 nm** | **412 MB** | 2× 内存换 **258×** 精度 |
| f32, band=4 | 48 nm | 824 MB | 4× 换 65×（不如 i16） |

换 f64 **零收益**——量化误差在**存的那一刻**就产生了，算的时候用多宽都救不回来。

`i16` 做成 `GridConfig` 的选项（`value_type: I8 | I16`），默认 `I8`。需要 µm 级验证时切 `I16`。

#### 2.5.7 三个前提

1. **`sdf_stock(p)` 的符号必须可信**。这一条由 §2.2 的钳制安全性证明保证：对减法 CSG，钳到 ±band 不丢符号。
2. **扫掠 SDF 的搜索精度不能降**。黄金分割迭代次数**按行程自适应（6–24 次）**：
   短段（0.05 mm）6 次就够，距离误差 < 1 µm；**200 mm 长段固定 6 次会到 16 µm**（实测），
   必须加到约 17 次。下限不要降到 2 次（误差 2.6×10⁻³ mm，会污染阈值）。
3. **`Full` brick 不能跳过**（§2.2 的漏洞），否则刀柄深埋实体时整段漏报。

### 2.6 凸体 × 凸体为什么是精确的

> **已实现**（2026-10-29，`collide::convex`，17 个测试）。下面是当初的论证；
> 实现细节与三个坑见本章末尾的「2.6.1 实现记录」。
> **穿透深度（EPA）也已落地**（`collide::penetration`，7 个测试）。

上一版说"旋转体离散成 16 边棱柱"，这会引入**外切误差**：`r(1−cos(π/16)) ≈ 0.019r`，对 R=30 的刀柄是 0.57 mm 的**系统性误报**。

正确做法：**不polygonize，直接用解析 support function 做 GJK**。GJK 只需要支持映射，不需要顶点表：

```rust
// 圆柱的支持点：轴向取两端，径向沿给定方向
fn support_cylinder(c: DVec3, axis: DVec3, r: f64, h: f64, dir: DVec3) -> DVec3 {
    let axial = if dir.dot(axis) > 0.0 { axis * (h * 0.5) } else { -axis * (h * 0.5) };
    let radial = (dir - axis * dir.dot(axis)).normalize_or_zero() * r;
    c + axial + radial
}

// 圆台同理（半径随轴向线性变化），球头是球，都是解析的
```

于是**凸体对凸体的碰撞是精确的**（浮点精度），误差为零。刀柄按 profile 拐点分解成若干圆台/圆柱/球——分解本身是精确的（旋转体在拐点处正好分段），不是近似。

这一条让"夹具/台面/机床 vs 刀具"这一类碰撞达到真正的**面片级（甚至解析级）**精度，而毛坯那一类由 §2.5.9 的 **1.6 µm（平面）/ 2.0 µm（曲面）** 下限兜底。

#### 2.6.1 实现记录

**形状**：`Cone`（圆台 / 圆柱 / 圆锥 / 退化圆盘）、`Sphere`、`Capsule`、`Box3`（有向）、
`Hull`（顶点表，给导入件用——只要顶点，不用三角化）、`Placed<S>`（局部形状 + 刚体变换）。
整把刀 = `cones_of(profile)` 的圆台并集；刀具不必凸，距离取各段最小即可。

**为什么算距离而不是判相交**：保守推进（§3）要的是距离下界来算安全步长，
布尔判定给不出这个量；顺带最近点对就是报告要的"哪里撞了"。

**性能**（release，单核）：

| 场景 | 耗时 |
|---|---|
| 单对 圆柱 vs 球（7.1 迭代） | **297 ns** |
| 整把刀（3 段圆台）vs 夹具 | **1.67 µs** |
| `aabb_gap` 粗筛 | 3.1 ns |

`distance()` 始终精确（最近点对就是报告要的位置），粗筛由独立的 `aabb_gap()` 提供。
早版本让 `distance()` 在 AABB 分离时直接返回盒间距离——快，但两个点变成盒面上的
近似位置，报告会说错地方。

**实现选择：穷举子集，不做增量单纯形维护。**
每轮把当前点集（≤ 4）里**含最新点**的子集（≤ 8 个）各求一次闭式最近点，取最小。
增量维护的经典 bug 是"该丢的点没丢"，只在少数几何下显形，且错了以后距离**偏小**
（更危险的方向）。闭式解 + 穷举是 O(1) 且不可能错；用定长数组（零堆分配）把成本补回来——
用 `Vec` 的版本是 2313 ns，定长数组版 297 ns（8×）。

**三个坑**：

1. **退化圆台（`half_h == 0`，平底刀的端面）不能按轴向正负挑端圆。**
   两端在同一个 z 平面上，`r_lo / r_hi` 是同心圆，凸包是半径 max 的那个圆盘。
   按 `d < 0` 挑 `r_lo` 会挑到圆心，距离虚高。
2. **非退化的圆台也要比较两端。** `f(端) = z_端·d + r_端·|dir_radial|`，
   轴向正负只说明 z 分量谁有利；当 `−2h·d` 与 `(r_lo − r_hi)·|dir_radial|` 反号时半径会翻盘。
   这一条让某随机用例的距离虚高 **0.06 mm**。
3. **上面两条都只有"支撑点合法性"测试能抓到。** KKT 最优性断言当时全绿——
   因为断言里的 `support` 和 GJK 里的是同一份错实现，两边一起错就自洽了。
   凡是"用同一份实现自证"的检查，都必须再配一条独立 oracle（这里是表面密采样）。

#### 2.6.2 穿透深度：EPA

`distance()` 在穿透时返回 0；`penetration()` 补上深度与分离轴。同样在 Minkowski 差
`W = A − B` 里做：原点到 `W` 边界的最近距离就是穿透深度。初始多面体由 GJK 的单纯形
扩成（不足 4 点就按"最远支撑点"补齐），然后反复"最近面 → 沿法向取支撑点 → 撑大"。

| 场景 | 结果 |
|---|---|
| 球 vs 球（解析 2.0） | 1.99998 mm |
| 盒 vs 盒（解析 0.5） | 0.50000 |
| φ6 圆柱插板（解析 1.0） | 1.00000 |
| 3 段圆台 vs 盒（平均 5.9 迭代） | 1.70 µs |

**验收方式是"照着推开"**：按报出的 `depth / axis` 移动 A，两体必须恰好接触（距离 < 1e-4）。
120 例随机穿透全部通过。这比"和解析解比"覆盖更广——解析解只对球、盒这类有闭式式的形状存在。

**两个坑**：

1. **符号**。`point_a − point_b` 在穿透时**不是**"从 b 指向 a"：因为 `point_a` 不再是
   "a 上离 b 最近的点"，而是"a 上扎得最深的点"。分离位移是 `−axis · depth`，
   字段因此叫 `axis` 不叫 `normal`。
2. **外法向不能用原点判朝向**。GJK 的单纯形贴着原点，原点可能正好落在某个面的平面上
   （`n·O = 0`），判不出哪边是外；判错的后果是最深的面被当成"最浅出口"，深度直接报 0。
   改用四面体重心（一定严格在内部）。

**精度边界**：曲面被多面体平面逼近，64 次迭代时球面误差 ~2e-5 mm，再往上只能靠更多面。
需要 µm 级深度的场景（比如过切分析）应该用解析特例，不是加迭代。

**仍未做**：`CollisionEpisode` 的聚类与 `sim` 接线。

## 3. 连续化：这是真正的风险点

### 3.1 问题

五轴快移速度：

| 速度 | 每 1 ms 位移 |
|---|---|
| 30 m/min | 0.5 mm |
| 60 m/min | 1.0 mm |
| 100 m/min | 1.67 mm |

薄壁、压板边缘、转台挡边都可以薄到 1–2 mm。**按 1 ms 采样，2 mm 的薄壁会被整步跳过，仿真报"无碰撞"而实际撞了。**

这不是精度问题，是正确性问题——一个漏报的碰撞检测比没有碰撞检测更危险，因为它给了虚假的安全感。

### 3.2 三种解法

| 方案 | 原理 | 问题 |
|---|---|---|
| 加密采样 | Δt 小到位移 < 最小特征/2 | 100 m/min + 1 mm 特征 → Δt < 0.3 ms，成本 ×3.3，且"最小特征"未知 |
| 扫掠体求交 | 构造运动体的扫掠体，与静态几何求交 | 旋转体扫掠体非凸，构造复杂；且五轴段内刀轴还在转 |
| **保守推进（CA）** | 用距离下界算安全时间步 | 需要可靠的距离下界 |

选 **保守推进**。它是自适应的：远时一步跨完，近时自动细分。

### 3.3 算法

```rust
/// 在一段运动 [t0, t1] 内找最早碰撞时刻
/// d(t)：当前位姿下的最小距离（下界）
/// v：该段内任意点的最大速度（由关节速度上界推出，见主方案 §4.7）
fn earliest_collision(
    pair: &Pair,
    t0: f64, t1: f64,
    d: impl Fn(f64) -> f64,
    v: f64,
) -> Option<f64> {
    const EPS: f64 = 1e-6;
    let mut t = t0;
    for _ in 0..64 {
        let dist = d(t);
        if dist < 0.0 { return Some(t); }          // 已相交
        if dist < EPS { return Some(t); }           // 接触
        let dt_safe = dist / v;                     // 这段时间内不可能撞
        if t + dt_safe >= t1 { return None; }       // 安全跨过整段
        t += dt_safe.max(1e-5);                     // 至少前进一点，防死循环
    }
    Some(t)                                          // 迭代耗尽，保守报碰撞
}
```

**关键点**：

- `v` 必须是**该段内任意点的最大速度**，不是刀尖速度。五轴摆动时刀柄末端的速度可能远大于刀尖（`|ω × r|`）。用主方案 §4.7 的关节速度上界推：`v = |v_tip| + max|ω_i| × r_max`。
- `v` 取上界 → `dt_safe` 取下界 → **永远不会漏报**。
- 迭代耗尽时**保守报碰撞**（宁可误报）。误报可以人工排除，漏报不行。

### 3.4 为什么这个方案便宜

- 刀具远离毛坯时（刀路 90% 的时间），`dist` 大 → 一步跨完整段，**1 次距离查询**。
- 接近时自动细分，但只在真正接近的那一小段。
- 最坏情况（沿壁面平行移动，距离恒为 0.5 mm）→ `dt_safe = 0.5/v`，会退化成加密采样。这是 CA 的已知弱点。缓解：距离变化率小于阈值时（平行运动）允许跨越，用"距离下界单调性"判断。

## 4. 安全间隙（v1.5，不在 v1）

主方案 A5 只要求"报出碰撞时刻与部件对"，不要求最小距离。但"快撞了"的预警很有用。

### 4.1 障碍：窄带 SDF 的带宽

窄带 band = 4 体素 = 0.4 mm（h=0.1）。SDF 在带宽外被钳制为 0.4，**无法区分"0.5 mm 远"和"50 mm 远"**。所以窄带 SDF 不能直接回答"距离是否小于 5 mm"。

### 4.2 解法：粗网格 EDT

加一层 **2 mm 分辨率的粗欧氏距离场**，覆盖毛坯 AABB + 20 mm 边距：

- 尺寸：200×200×100 + 边距 @ 2 mm → 约 120×120×70 = 1.0e6 格
- 存储：i16（单位 0.1 mm）→ **2 MB**
- 构建：从毛坯 band 体素出发做**可分离欧氏距离变换**（Felzenszwalb，两遍扫描，约 60 行）
- 更新：只重算脏 brick 对应的粗格（增量）

粗筛用粗 EDT（误差 ≤ 2 mm），进入 2 mm 以内再用窄相精确判定。

**这是纯自研、复用现有体素结构、2 MB 内存的方案**，比引入通用几何库便宜得多。

## 5. 毛坯演化对碰撞的影响（关键）

毛坯在加工过程中形状持续变化，碰撞判定不能只做一次。这一节把影响拆成六条，其中 5.3 是本方案成立的关键论证。

### 5.1 三类必须重算的情形

| 情形 | 例子 | 后果 |
|---|---|---|
| **新表面出现** | 去除材料产生型腔壁；刀柄撞上 1 秒前还不存在的面 | 漏报（最危险） |
| **旧表面消失** | 原本挡路的材料被切掉 | 误报 |
| **可通行空间变化** | 粗加工后刀柄能进型腔；精加工时可能贴壁 | 需逐步评估 |

**结论**：碰撞必须随加工逐步评估，不能只在开头和结尾各做一次。这也是为什么碰撞必须和去除引擎跑在同一条数据流上——用同一份毛坯状态。

### 5.2 顺序：先去除，后碰撞

```
SimStep (关节值 + 刀具位姿)
   ├─→ ① 去除引擎：更新 SDF（脏 brick + 状态重分类）
   └─→ ② 碰撞引擎：查询 SDF（同一份数据）
```

顺序颠倒会怎样：刀杆会撞上**已经被切掉的材料**——典型误报场景是螺旋下刀，刀杆跟着刀具进入型腔，而型腔是本段刚挖出来的。先碰撞后去除，刀杆会被"本段即将消失的材料"判为碰撞。

### 5.3 段内不一致性——以及它为什么可以忽略

这是最容易被忽略的坑。

**问题**：保守推进（§3.3）会在**段内**的中间时刻 t 查询距离 `d(t)`，但毛坯只有**段级**的更新粒度——`d(t)` 实际是拿"段末毛坯"算的。严格说，段内任意时刻的毛坯状态 `stock(t) = stock_pre − sweep(0..t)`，而 `stock(1) = stock_pre − sweep(0..1)` 是它的子集，即**段末毛坯更"空"**。用更空的毛坯算距离 → 距离偏大 → 可能漏报。

**为什么可以忽略**：因为两种效应**在物理上不同源，且不会同时放大**。

| | 材料去除速率 | 刀柄运动速率 |
|---|---|---|
| 决定因素 | **刀尖进给** | 刀尖速度 + `\|ω\|·r_max` |
| G1 切削 3000 mm/min | 0.05 mm / ms | 0.05–1.5 mm / ms |
| G0 快移 100 m/min | **0** | 1.67 mm / ms |

两条结论：

1. **切移动时毛坯变化极慢。** 即使进给拉到 10000 mm/min（167 mm/s），每毫秒也只切掉 0.167 mm 材料。而碰撞安全间隙通常 ≥ 1 mm。
2. **快移时毛坯完全不变化。** G0 不切削。所以"穿透薄壁"（需要 1.67 mm/ms）和"毛坯演化"（需要高切削速率）**永远不会同时发生**。

这正是 §3 的保守推进能成立的前提：**穿透风险只存在于不切削的快移段，而快移段毛坯是静止的**。

**兜底措施**：碰撞 margin 取 `feed_per_step × 2 + h`（切削时约 0.1 + 0.1 = 0.2 mm）。这个 margin 同时覆盖了段内不一致性与体素离散误差。

> 如果将来要更严格（例如支持高速切削 HSM，进给 20000 mm/min 以上），可以把切削段按 0.1 mm 弧长再细分一次碰撞子步——但这不是 v1 的需求。

### 5.4 brick 状态迁移：必须做，否则误报

毛坯演化不只是"距离值变小"，还包括 **brick 状态的迁移**。`SparseGrid` 有三种状态（ADR-002 §3.1）：`Empty` / `Full` / `Band`。

每次切削后，被触碰的 brick 必须**重分类**：

```rust
fn reclassify(grid: &mut SparseGrid, id: IVec3) {
    match grid.bricks.get(&id) {
        Some(BrickState::Band(v)) => {
            let band = (BAND as f64) * grid.h;
            if v.iter().all(|&d| (d as f64) * grid.h >= band) {
                // 整块都被切空了 → 降级为 Empty，释放体素数组
                grid.bricks.insert(id, BrickState::Empty);
            } else if v.iter().all(|&d| (d as f64) * grid.h <= -band) {
                grid.bricks.insert(id, BrickState::Full);
            }
        }
        _ => {}
    }
}
```

**为什么这是正确性问题而不只是内存优化**：

- `Full` brick 在碰撞里意味着"整块都是材料"。如果一块砖被切空却仍是 `Full`，碰撞引擎会把"穿过空腔的刀杆"判为碰撞 → **持续误报**。
- `Empty` brick 可以**永久跳过**（我们只去除材料，永不加料）。这是单调性，可以直接用来做粗筛：碰撞只需要遍历 AABB 内的 `Band` brick。

`Full → Band` 的迁移在去除引擎里已经要做（ADR-002 §3.4 的 `materialize`），`Band → Empty` 是这里新增的、容易被漏掉的一条。

### 5.5 碰撞事件要聚类成"episode"

刀杆沿着型腔壁拖动 3 秒，会产生几千条碰撞事件。直接列出来用户没法看。

```rust
pub struct CollisionEpisode {
    pub a: BodyTag, pub b: BodyTag,
    pub t_start: f64, pub t_end: f64,      // 起止时刻
    pub block_start: u32, pub block_end: u32,
    pub max_penetration: f64,               // 最深穿透
    pub worst_position: DVec3,              // 最深点的位置（用于 3D 高亮）
}
```

聚类规则：同一对部件、时间间隔 < 50 ms 的连续事件合并为一个 episode。报告只列 episode，UI 在时间轴上用一段红色区间表示。

### 5.6 不支持"从中间继续仿真"

用户拖到 50% 再点"继续仿真"，需要恢复该时刻的毛坯状态。三条路：

| 方案 | 代价 | 结论 |
|---|---|---|
| 定期快照 | 130 MB/次 × 10 次 = 1.3 GB | 不可接受 |
| 增量撤销 | 需要记录每次切削的逆操作，实现复杂且易错 | 不值得 |
| **从头确定性重算** | 100k 段 × 0.2 ms ≈ 20 秒 | **采用** |

重算是确定性的（同样输入必得同样输出），所以"继续仿真"= 后台从头跑到目标时刻再接着算。20 秒的等待对自用工具可以接受，而且实现上零风险。

**推论**：碰撞事件不需要持久化到磁盘，也不需要增量更新——每次重算都重新产生。这省掉了整个"历史状态管理"模块。

### 5.7 同一个线程

碰撞与去除都访问 `SparseGrid`，放同一个后台线程串行执行，避免锁。碰撞是只读的，开销远小于去除（§8：碰撞约 0.05 ms/步 vs 去除 0.2–6 ms/段），串行的代价可忽略。

碰撞只需要遍历刀具 AABB 覆盖的 brick——这个信息在 `HashMap<IVec3, BrickState>` 里直接查，无需额外索引结构。

## 7. 测试策略（TDD）

碰撞检测的测试必须是**可证伪的**——不能写 `assert!(collision.is_some())`，要断言**具体时刻和部件对**。

### 7.1 已知答案的几何对

```rust
#[test]
fn obb_pair_distance_is_exact() {
    let a = Obb::new(DVec3::ZERO, DVec3::splat(10.0), DMat3::IDENTITY);
    let b = Obb::new(DVec3::new(25.0, 0.0, 0.0), DVec3::splat(10.0), DMat3::IDENTITY);
    // 两盒 x 向半宽各 5，中心距 25 → 距离 15
    assert!((distance_obb_obb(&a, &b) - 15.0).abs() < 1e-12);
}
```

### 7.2 穿透反例（最重要）

```rust
#[test]
fn fast_rapid_through_thin_wall_is_detected() {
    // 2 mm 薄壁，刀杆以 100 m/min（1.67 mm/ms）穿过，采样周期 1 ms
    // 朴素离散采样：t=0 在壁前 0.8mm，t=1 在壁后 0.87mm → 全部"无碰撞"（漏报）
    // 保守推进：必须在 0 < t < 1 之间报出碰撞
    let hit = earliest_collision(/* ... */);
    assert!(hit.is_some(), "薄壁穿透漏报");
    assert!(hit.unwrap() > 0.0 && hit.unwrap() < 1.0);
}
```

**这个测试必须先红**——先写一个朴素的离散采样实现，确认它在这个用例上失败（漏报），再换成保守推进让它变绿。否则你无法确认 CA 真的解决了问题。

### 7.3 误报测试

```rust
#[test]
fn holder_above_stock_no_collision() {
    // 刀杆底面距毛坯顶面 5 mm，全程无接触 → 必须报无碰撞
    assert!(run_collision_check(&path).is_empty());
}
```

漏报和误报要成对测。只有漏报测试会诱导出"永远报碰撞"的实现。

### 7.4 与 cutrail 对拍（第一步的 oracle）

`cutrail` 的 `CutReport` 里有 `Collision` 字段，`EngineOptions` 有 `collision check` 开关——它做 shank/holder 碰撞检测。

第一步（ADR-003 §6，暂借 cutrail 当脚手架）时，**同一批刀路分别跑我们的碰撞与 cutrail 的碰撞，比对"碰撞/不碰撞"与时刻**。允许我们的结果更保守（多报），但不允许漏报。

```rust
#[test]
fn our_collision_is_at_least_as_strict_as_cutrail() {
    let ours = run_our_collision(&path);
    let theirs = run_cutrail_collision(&path);
    for c in &theirs {
        assert!(ours.iter().any(|o| (o.at_time - c.at_time).abs() < 1e-3),
                "cutrail 报碰撞而我们漏报：{:?}", c);
    }
}
```

### 7.5 毛坯演化测试（§5 的正确性验证）

这类测试最容易漏，因为**只用静态毛坯测不出来**。

**(a) 进入刚挖出的型腔 → 不能误报**

```rust
#[test]
fn holder_entering_fresh_pocket_is_not_a_collision() {
    // 1. 用 φ6 刀螺旋下刀挖一个 φ10 的型腔（深 30 mm）
    // 2. 随后刀杆随刀具进入型腔（刀杆在型腔内部，但不碰壁）
    // 3. 必须报"无碰撞"
    // 如果忘了 §5.2 的顺序（先碰撞后去除），这里会误报
    let episodes = run_collision_check(&pocket_path);
    assert!(episodes.is_empty(), "型腔进入误报：{:?}", episodes);
}
```

**(b) 贴着型腔壁拖动 → 必须报，且聚类成 1 个 episode**

```rust
#[test]
fn holder_dragging_along_pocket_wall_is_one_episode() {
    let episodes = run_collision_check(&drag_path);
    assert_eq!(episodes.len(), 1, "应聚类为一个 episode，实际 {:?}", episodes);
    assert!(episodes[0].max_penetration > 0.0);
    assert!(episodes[0].t_end > episodes[0].t_start);
}
```

**(c) brick 降级**

```rust
#[test]

    let mut grid = stock_block(60.0, 40.0, 20.0, /*tile*/ 10.0);
    cut_through(&mut grid, /* 一刀切穿整个 10mm brick */);
    for id in grid.touched_bricks() {
        assert!(!matches!(grid.bricks[&id], BrickState::Full),
                "brick {id:?} 已切空但仍为 Full → 会持续误报");

```

**这三个测试都要先红**：先用"静态毛坯 + 单一时刻检查"的朴素实现跑，确认 (a) 误报、(c) 失败，再逐条修好。

### 7.7 随机对拍：把"不会漏报"变成可验证的

§2.5 的检出下限是**推导**出来的。推导可能错，所以必须有测试来证伪它。

思路：构造**解析可算真值**的场景，随机撒位姿，断言"真值穿透 > 阈值 ⇒ 必须报碰撞"。

**(a) 圆柱 vs 半空间（解析真值）**

> 下面用 `proptest!` 是为可读性；实现时改用 `kin/tests/roundtrip.rs` 那套**固定种子 xorshift**
> （ADR-003 §2 修订：proptest 已移除，理由是两条被上游钉死的传递依赖）。

```rust
proptest! {
    /// 毛坯 = 半空间 z<0，刀杆 = 半径 R 的圆柱，姿态随机、位置随机
    /// 解析穿透深度 ε 可精确计算 → 真值无误差
    #[test]
    fn never_misses_penetration_above_5um(
        r in 3.0f64..40.0,
        tilt in -60.0f64..60.0,
        eps in 0.0f64..1.0,
        seed in 0u64..1000,
    ) {
        let (grid, holder) = setup_halfspace_case(r, tilt, eps, seed);
        let truth = analytic_penetration(&holder);      // 精确
        let hit = revbody_vs_stock(&grid, &holder, ...).is_some();
        // 阈值取 5 µm ≈ 2.5 倍最坏下限（2.0 µm）。不能取 1 µm：
        // 断言"1 µm 也必检出"就是在断言一件按定义做不到的事，测试会随机红。
        if truth > 5e-3 {
            prop_assert!(hit, "漏报：真实穿透 {} mm，R={}，tilt={}", truth, r, tilt);
        }
    }
}
```

> **这个阈值本身是个坑**：早期写的是 `truth > 1e-3`（1 µm），注释还写着"方向 B 的保证是 0.17 µm，留 6 倍裕度"。
> 1.6–2.0 µm 的下限一确认，这个测试就变成了"断言一件做不到的事"——随机对拍会间歇性失败，
> 而失败原因看起来像"实现有 bug"。**测试阈值必须由保证下限反推，不能凭"看起来很小"来定。**

**(b) 回归：刀杆深埋（§2.2 的 `Full` brick 漏洞）**

```rust
#[test]
fn holder_deep_inside_solid_block_is_detected() {
    // 毛坯 200×200×100 未加工（全部 Full brick），刀杆从侧面斜插进去 20 mm
    // 原实现（跳过 Full brick）会漏报
    let hit = revbody_vs_stock(&grid, &holder, ...);
    assert!(hit.is_some(), "刀杆深埋实体内漏报 —— Full brick 未被测试");
}
```

**(c) 对照：与密集采样参考实现比对**

对复杂毛坯（已加工的型腔），用 10 倍密集的采样做参考（h=0.01 mm 的离线参考，跑得慢但只用于测试），断言我们的结果不弱于参考。

**这三个测试的定位**：(a) 是主证据，(b) 是刚发现的漏洞的回归锁，(c) 是复杂形状的兜底。**全部要能在 CI 里跑**——(a) 用 proptest 限 200 个 case，(c) 用固定 5 个场景。

## 8. 性能预算

| 环节 | 每步成本 | 100k 步总计 |
|---|---|---|
| 粗筛（1250 次 AABB） | 25k flops | ~0.05 s |
| 窄相 GJK（约 5% 通过粗筛，约 60 对） | 60 × 1 µs | ~6 s ⚠ |
| 窄相 SDF（仅刀具贴近毛坯时，<5% 步） | 1e4 × 30 flops | ~0.5 s |

GJK 那 6 秒是主要开销。优化：

1. **关节对静态化**：机床部件只随关节运动，可预计算"哪些关节组合下这两件可能接近"（查表），运行时跳过不可能的对。这一条通常能砍掉 80%。
2. 粗筛用**球**而非 AABB（更快，略保守）。
3. 只在**距离变化率大**的步做 GJK，其余用上次结果外推。

目标：< 3 秒 / 100k 步。
