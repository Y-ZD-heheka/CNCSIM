# ADR-008 显示 LOD 与网格预算

> 状态：**已实现**（2026-10-29，`voxel::lod`，11 个测试）
> 日期：2026-10-29
> 关联：ADR-002 §4（不做过切判定的网格）、ADR-006 §7（提取实测规模）、主方案 §8（渲染预算）

---

## 0. 结论

三句话：

1. **显示网格重新采样，不抽稀。** 输入是 2 MB 的稀疏树，不是 834 MB 的细网格；水面由 Surface Nets 的结构保证，不靠误差度量兜。200 mm 毛坯 @ h=0.1：**3200 万面 / 834 MB / 43 s → 200 万面 / 52 MB / 2.2 s**（k=4）。

2. **`k ≤ band_voxels` 是几何约束，不是调参旋钮。** 粗格边长超过窄带宽度后，跨符号棱的远端被钳制，插值不再等于真实距离，偏差没有上界。所以 `extract_surface_lod` 超限直接 panic，不静默产出错网格。

3. **LOD 顺手暴露了一个真 bug：窄带只在切面一侧完整。** 修完之后碰撞（用同一套插值）和显示都受益，代价是切削 AABB 外扩一个 band：200 mm 直槽遍历 1.34 M → 2.07 M 体素，893 → 1004 ms。

---

## 1. 为什么不是网格抽稀

| | 网格抽稀（QEM / 边折叠） | 粗格重采样（本模块） |
|---|---|---|
| 输入 | 先得把 3200 万面 / 834 MB 造出来 | 稀疏树，2 MB（全由 tile 表达） |
| 水密性 | 抽稀会开洞，靠额外约束守 | **Surface Nets 结构保证** |
| 可复现 | 依赖误差度量与堆序，两次跑可能不同 | **纯函数，逐位可复现** |
| 代码量 | 上千行 + 一堆启发式阈值 | 复用 `vertex_of` / `emit_quads`，约 200 行 |
| 精度 | 保形好（误差度量驱动） | 均匀粗化，曲率大处不如抽稀 |

决定性的是前两行：抽稀的输入本身就是"不可渲染的 834 MB"，而**本项目只在显示层做降级，几何真相永远是细格**，所以均匀粗化带来的精度损失不进判定链（ADR-002 已定：过切用解析扫掠点测试，不用网格）。

## 2. 那条约束的推导

粗格边长 `h_c = k·h`。一条**跨符号**的棱，两个端点分别在表面两侧，所以各自到表面的距离 `≤ h_c`；而窄带半宽是 `band_voxels·h`。

- `k ≤ band_voxels`：两个端点都落在带内 → 存储值就是真实距离 → 零点插值误差只剩曲率项 `O(h_c²/R)`。粗格格点又刻意与细体素中心重合，所以连三线性插值误差都没有（权重退化成一个 1）。
- `k > band_voxels`：远端被钳制到 `±band`，插值**不再等于真实距离**，偏差随 `(h_c − band)²` 增长。

实测（R=6 球，`band=4` 体素 → `band_mm=0.4`，顶点到真实球面的最大径向偏差）：

| k | h_c | 三角形 | 最大径向偏差 |
|---|---|---|---|
| 1 | 0.1 | 135 648 | 1.8 µm（量化半档 1.58 µm + 曲率） |
| 2 | 0.2 | 33 912 | 3.3 µm |
| 3 | 0.3 | 15 048 | 6.2 µm |
| **4** | **0.4** | **8 460** | **9.8 µm** |
| 5（越界） | 0.5 | 5 364 | 15.5 µm |
| 6（越界） | 0.6 | 3 768 | 34.2 µm |

越过 band 之后不是断崖，是**没有上界**：k=6 已经 34 µm，k=8 量级到 0.1 mm。而且它悄悄发生——网格看起来还闭合、还水密，只是位置在漂。这就是为什么要 panic 而不是 warning。

**推论（重要）**：想再少面，只能**加宽 band**（`band_voxels` 5→6，内存 ×1.25~1.5），不能加大 k。默认 `band=4` / `h=0.1` 的 `h_c ≤ 0.4 mm` 正好把 200 mm 毛坯压到 200 万面——这个"巧合"是选的：

```
三角形数 ≈ A / h_c² × 2
200 mm 毛坯 A ≈ 160 000 mm²  @ h_c=0.4 → 2.0 × 10⁶
```

## 3. 实现要点

### 3.1 只处理表面附近的粗格

200 mm 毛坯 @ `h_c=0.4` 有 **1.25 亿**个粗格，全扫一遍十几秒。候选格从**叶**反推：表面穿过某格 ⇒ 该格 8 个角点混号 ⇒ 混号一定牵连某片"可能被表面穿过"的叶。

判 hot 的**三档**判据（任何一条成立）：

| 判据 | 抓什么 | 漏了会怎样 |
|---|---|---|
| 叶内混号 `NEG∧POS` | 窄带正常、表面就在叶内 | 网格中部开洞 |
| 叶内有窄带体素 | 缓坡：一侧全饱和，另一侧才进带内 | 缓坡丢面 |
| 26 邻里有反号叶（未分配 = 背景 = 材料外） | **二值场**：`fill_box` 的毛坯、切空的区域 | 毛坯外表面整张丢失 |

第三档是第一版栽的坑：只按 `|v|` 判，60 mm 方坯 k=1 提取出 **0 个顶点**——`fill_box` 填的是 ±MAX 的二值场，窄带空空如也。

候选格范围：`p ∈ [⌊(lo−k)/k⌋, ⌊hi/k⌋]`（"8 个角点里至少一个落在这片叶内"）。

实测（200 mm 毛坯）：候选格 **2 970 126** 个，真正出顶点的 1 000 002 个（3 倍余量），
而全空间是 1.25 亿——少 **42 倍**。k=2 时是 1980 万个，这也是 k=2 慢 10 倍的原因之一。用 `div_euclid` 而不是 `/`：负数下 floor 语义才和树的位运算索引一致，这是 `tree` 已经踩过的同一个坑。

### 3.2 复用而不是另写一套

`vertex_of` / `emit_quads` / `push_vertex` 从 `extract` 提到 `pub(crate)`，粗细两档共用**同一段绕序逻辑**。绕序一旦写两遍，早晚只改一处。

### 3.3 可复现

- `for_each_leaf` 走 HashMap，顺序随机 → 叶先排序。
- 候选格进 `HashSet` 再摊平成 `Vec` → 排序。
- 顶点按排序后的格序生成，四边形按顶点创建顺序发射。

三条合起来让两次运行的网格**逐位相同**，与细格同一条硬门槛。

### 3.4 角点缓存

一个格点最多被 8 个粗格共用，不缓存等于把 `sdf()` 重复算 8 次。加一张 `FxHashMap<[i32;3], f64>`：k=2 从 31 → 25 ms，k=4 从 5.0 → 3.8 ms（同一个 12×12×8 mm 块）。

### 3.5 实测

| 场景 | 结果 |
|---|---|
| 12×12×8 mm 块 + 槽，k=1 | 136 800 面 / 215 ms（**比细格慢 7 倍**，见下） |
| 同上 k=2 | 34 200 面 / 25 ms |
| 同上 k=4 | 8 520 面 / 3.8 ms |
| **200 mm 毛坯 k=4** | **2 000 000 面 / 52 MB / 2.24 s / 丢洞 0** |
| 200 mm 毛坯 k=2 | 8 000 000 面 / 208 MB / 21.8 s |

k=1 比细格慢是因为候选格是"叶内 8³ + 一层 halo"，一颗一颗查哈希，而细格走的是每叶 10³ 的连续缓冲。**k=1 只用于和细格逐位对拍，生产不用**——预算公式也不会选它。

k=2 的 21.8 s 也不正常地慢（是 k=4 的 10 倍，而不是 4 倍）：8 M 顶点的角点缓存把 200 MB 级随机访问压进 L2 之外。真要 k=2，缓存该换成按块处理。

## 4. 顺带修掉的一个真 bug：窄带单边完整

LOD 测试第一次跑就红了：槽底偏 **97 µm**（真值 0 差）。

根因不在 LOD，在 `cut`：扫掠 AABB 只到刀尖平面，刀尖以下的材料侧只有 1 个体素（AABB 取整余量）拿到真实距离，**再往下全是切前的饱和值 `−band`**。

于是粗格格点（间距 0.4 mm）正好落在饱和区上，插值被拽偏：

```
真值：z=6.85 处 d = −0.15
错误：z=6.85 处 d = −0.40（切前饱和）
插值：t = 0.4/(0.4+0.2488) = 0.616 → 顶点 7.0966（真值 7.0）
```

细格为什么没错？因为它恰好有一层 6.95/7.05 的体素在带内，靠 1 个体素侥幸正确——那是运气，不是设计。

**修法**：AABB 外扩 `band_voxels` 个体素。新表面落在扫掠体边界上，所以"到新表面距离 < band"的体素一定落在"扫掠体 ∪ band 邻域"里。

**代价**（200 mm 直槽 φ6、切深 1 mm）：

| | 修前 | 修后 |
|---|---|---|
| 遍历体素 | 1.34 M | 2.07 M |
| 耗时 | 893 ms | 1004 ms |
| 0.05 mm 段（真实段长） | 11.0 ms | 13.4 ms |
| 外推 10 万段 | 18.3 min | 22.4 min |

**这不是显示问题**：碰撞用的也是同一套三线性插值（ADR-004 §2.5）。窄带单边完整时，刀刚切过的面附近插值会系统性偏向材料侧——正好是"漏报碰撞"的方向。

新增测试 `band_is_complete_below_the_cut_surface` 锁住这条：槽底以下 0.15 / 0.35 mm 的存储值必须是 `−0.150 / −0.350`，而不是 `−0.4`。

## 5. 按预算选档

```rust
pub fn choose_lod_factor(fine_triangles: usize, budget: usize, max_factor: u32) -> u32
```

`k = ⌈√(T_fine / budget)⌉`，夹到 `[1, max_factor]`。`max_factor` 就是 `band_voxels`。

**夹到上限仍超预算时不静默接受**：调用方（将来的 `render`）要能区分"降级成功"与"降级后仍然太大"。现在这个信息由调用方自己比一次 `triangles > budget` 得到——`choose_lod_factor` 不返回 `Result`，因为"预算不够"不是错误，是待定策（要么加宽 band，要么接受更多面）。

`budget = 0` 当作"没给预算"，退回 k=1，而不是当成"无穷小"除出天文数字。

## 6. 精度账单

| 项 | 量级 | 会不会进判定链 |
|---|---|---|
| `i8` 量化半档 | 1.58 µm | 是（细格，ADR-004） |
| 三线性重建 | `h²/(8R_c)`（平面 0） | 是（细格） |
| 粗格顶点（k=4，R/h_c=15） | 9.8 µm | **否**，只进显示 |
| 粗格体积误差（R=6 球） | k=1 0.05% / k=2 0.19% / k=4 0.73% | 否 |

体积误差按 `(h_c/R)²` 长，与理论一致。0.73% 对 R=6 的小球是 12 µm 量级的半径偏差，200 mm 零件上肉眼不可见。

**一句话**：显示网格的误差预算按"四分之一个粗格"（100 µm）算都还有 10 倍余量，而所有判定都用解析扫掠，不用网格。

## 7. 还没做的

| 项 | 为什么现在不做 |
|---|---|
| 自适应 LOD（曲率大处细） | 需要八叉树式跨级拼接（过渡格），是另一个量级的复杂度；先有全局 k 把预算压住 |
| 视距分档 | 机制已就绪（`extract_surface_lod` 可反复调），缺 `render` 层 |
| 法向质量 | 粗格法向用 8 角点差分，曲率大处偏；可改为在细格上取梯度再平均 |
| k=2 的缓存局部性 | 需要按块（level-1 节点）批处理，等真有 k=2 的需求再做 |
