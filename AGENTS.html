1. 这是什么

Bevy + Rust 的五轴 CNC 仿真验证器，另带一个 3 轴简化 CAM（STL → 高度场 → G 代码）用于自造测试程序。

只回答四个问题：会不会撞、会不会过切、实际跑多久、哪里出问题。

纯自用，不对外分发。 由此可以读/抄 LinuxCNC（vismach、5axiskins.c、g-code.adoc）；但 GrabCAD 的"非商用"限制的是使用场景，公司商用仍适用 → 机床外观一律参数化生成。

4. 硬规定（违反即返工）

  1. Edition 2024（resolver = "3"）；第三方依赖只用精确最新稳定版 version = "=x.y.z"，禁止 ^。加依赖前先 check_versions.py --show <crate>。
  2. L0–L3 零 Bevy 依赖——正确性必须能纯 cargo test 锁定。
  3. 没有 cncsim-core；禁止 common / utils / types / shared 这类名字。
  4. collide 不依赖 voxel（DistanceField trait 反转，接线在 sim::stock）。
  5. gcode 不做运动学（输出位姿不是关节值，RTCP 归 kin）。
  6. ui 只依赖 hmi，不直连 sim。UI 需要的 Alarm/Severity 由 hmi 显式重导出。
  7. SparseGrid 单一所有者，跨线程只走 channel。禁止 Arc<Mutex<SparseGrid>>。
  8. 结果必须逐位可复现——任何破坏确定性的优化都不接受，哪怕更快。
  9. 不建共享 Diagnostic 枚举：各层自带 finding，sim 组合。
  10. Pose.axis 是单位向量，由刀尖指向主轴（A=0 → +Z）。

工作方式

  • TDD 强制：红 → 绿 → 重构。先写测试、跑一次确认它因正确的原因失败（不是拼写错）。禁止先写实现再补测试。
  • 每个测试必须能被证伪：断言要具体到能区分"做对了"和"做错了"。assert!(x.is_ok()) 不算。
  • 交付时报告红绿过程：先写了什么测试、它如何失败、再如何通过。主动证伪（改坏一处 → 跑 → 复原）。
  • 声称"完成"前必须实际跑过构建和测试，报告真实输出。发现自己的说法被实测推翻时明确更正，不静默改口。

形位公差 ✅ sim::form：ISO 1101 最小区域法评平面度/圆柱度（区域宽度 max−min，基准用八方向模式搜索优化），同时给 LSQ 值作对照；表面点沿实际场梯度投影得到。分片=位置连通+法向 12°；分不出特征的归 Freeform 只报偏差。桌腿件 h=0.6：两个平面 0.028 / 0.360 mm（差 13 倍，整件均值看不出来）

可达性分析 ✅ sim::reach：对每个设计面采样点判「面朝 + 射线不被挡」（球体追踪），存 facing/masks 两张位图；够不到的面按空间连通块分组并给建议方向、A/C、bbox。封闭内腔（法向各向抵消）如实报「没有单一方向」而不是丢掉
工序编排 ✅ --multi 把整个可达半球（A≤110°、25 个候选方向）当候选集，用带权集合覆盖贪心选方向：3 轴与 3+2 在这里只是"方向不同"，用哪种由覆盖面积决定。桌腿件 78.6% → 86.4%（= 几何上限）。--no-auto-pass 关掉
多方向保真度口径 ✅ 三个口径并排：体素（surface_dev，分辨力≈h）/ 解析（sweep_deviation，与 h 无关，点到刀具扫掠体并集的有符号距离）/ 体积（compare_with_design）。桌腿件 h=0.6：体素 合格 81.6% / 过切 5.8% / 最大 +1.55；解析 85.0% / 0.6% / +0.27。逐点归因（attribute_points）证明体素报的过切里 79% 没有任何刀具扫过——薄于一个体素的尖角被判成空气。验收看解析值；行距/坡度两个旋钮实测无效（见 §39）
精加工刀径 ✅ 默认按工件尺度 (短边/18).clamp(0.8,3.0)，--finish-d 覆盖。这是唯一有效的保真度杠杆（凹角残料 R(1/sin(θ/2)−1) 面积 ∝ √R）：Ø3 85.0% / Ø1.5 91.6% / Ø1.0 94.1%，切长 45 / 84 / 123 m
刀路体检 ✅ --dry（RunConfig::dry_run）：只走刀路不切材料，解析口径的数字一模一样（测试钉住段数/端点/刀号逐段一致）。桌腿件 139527 块 424 s → 51 s（8.3×），调刀路时用它，最后再跑一次全量仿真出体积/预览
多线程利用率 ✅ 报告加五项拆分（切削/比对/其它/线程/单批并行片数）。三处修复：解析扫描并行（150 → 22.5 s，1 线程 151 s 对拍）、MIN_PAR_WORK 改判各段 AABB 体积和（细长批以前永远不进池）、分片从 1D 改三轴并按片数乘积控制（片数 1 → 60）。桌腿件 22 道 h=0.6：339 → 76.5 s（最好）/113 s（中位），结果逐位一致
比对性能 ✅ 解析过切加段空间索引 + 两段扫描（区域细扫 + 全局 8× 粗扫）：桌腿件 9 道 h=3 的仿真 158.8 → 38.5 s（4.1×），其中解析过切 135.8 → 16.0 s；gouge_max_depth 与逐点值差 2%
刀杆碰撞 ✅ Process::check_shank：普通球头/平底刀 + 无倒扣时不需要查（drop-cutter 已保证整根刀柱在外）；锥度刀或有倒扣时建 MeshIndex（XY 分桶 + 点—三角形距离），沿刀轴从刃长以上取样，距离 < 刀杆半径 + 间隙 就放弃该点、留料，计入 Stats::shank_skips
落刀几何 ✅ 球头/平底刀都是 drop-cutter：球头刀心 = max(z + √(R²−d²))，平底刀 = max_within。替代原来的"刀尖 = 曲面 + R·n"——后者在凹角处会让球贴墙啃进去（实测 1.35 mm ≈ 一个刀半径）
开粗效率 ✅ ap = 1.0×D、ae = 0.7×D、vf = 600+120D，MRR 打印出来（Ø6 时 33.3 cm³/min）；法向留量 0.3 mm 给精加工
避空颈长 ✅ ToolSpec.neck_mm + neck_top() + radius_at 四段（刃豁免 / 等径颈查 / 30° 缩颈查 / Ø6 柄查）。flute_mm 不能兼任颈长——加 flute 等于把碰撞豁免区跟着加长（flute 16→25 时 Ø1 刀"切入啃" 3→249、合格率 96.5→95.7%）。颈才是 Ø6 柄之后的真杠杆：+9 mm 颈把柄挡在通道外（20.3→29.3 mm 介入），叶轮刀杆撞 7516→1177（−84%）、合格率 96.5→98.0%（残料 0.4%）；桌腿件 +12 无害 97.0%。默认颈 = 22% 工件高（叶轮 9.0），曲面刀默认改 Ø0.8（球面闸门拒绝 3309→214）。--surface-neck 覆盖（§51）
刀柄直径 ✅ ToolSpec.shank_diameter + shank_radius()，CLI --shank-d（默认 6.0，真实刀具统一 Ø6 h6 夹持）。to_tool_def() 的柄剖面改成 刃顶 → 30° 缩颈 → Ø6 → 顶，shank_hits 与 surface::shank_hits_axis 都改吃 shank_radius()。之前柄等于刃径，碰撞检查偏乐观。判据分三段（radius_at）：切削刃 0…flute 不查（材料要切掉）、避空缩颈 flute…flute+taper 按该高度实际半径查、刀柄按 Ø6 查——拿柄径一刀切会把避空段也当 Ø6，虚报 42~72%。叶轮 1 98.2% → 96.6%（残料 0.2 → 1.8%）、桌腿件 97.8% → 96.9%（残料 1.0 → 1.9%）。--shank-d 0 逐位复现旧值（§49）
工件包络 ✅ MachineConfig.work（Ø400 / 高 340）：件装不下就自动等比缩小（min(1, 200/r, 340/h)×0.99，中心取毛坯 XY 中心 + 底面），比例打印出来；--no-shrink 保持原尺寸并标红。实测 Ø707×400 → 0.560× → Ø396×224
凹角清根 ✅ Job.rest / Pass.rest → RestMask（目标点按刀半径外扩成格子位图）→ 只在这些格子出刀，空行不生成 G 代码。两阶段：先 --dry 拿解析残料（0.15–1.0 mm），再补 Ø0.7 长颈小刀（刃长 3 mm）。桌腿件 91.6% → 93.7%，过切不变（1.2%），切长 +29%（84 → 108 m）；比全局换 Ø1.0 更划算（94.1% 但过切 1.9%、123 m）
清根安全阀 ✅ ball_hits：球心到真网格的距离 ≥ R − 0.03（高度场看不见悬伸，小刀会钻到下面啃 0.27 mm）。清根道的刀杆判据改判"侵入 ≤0.15"而不是"留 0.5 间隙"——凹角里刀本来就是相切的
侧向工序的过切 ✅ --no-side：去掉 ±X/±Y 定轴侧向道。桌腿件 97.8% → 97.6%、过切 1.2% → 0.1%，而且 F1@0.15 0.868 → 0.930、IoU 0.9516 → 0.9769、Chamfer 0.175 → 0.089（都比"无曲面道"的基线更好）——侧向工序真的在啃 0.3 mm，只是原来被残料盖住了。叶轮 1 反过来 98.2 → 94.7%（通道大块料还得靠侧向开粗）。开关不是默认，判据是"侧向道会不会啃倒扣 + 曲面道覆盖得动"（§48）
口径对账 ✅ --vcheck：毛坯按 0.9 mm 格逐点问"在不在扫掠体里"，得与 h 无关的去除体积，跟体素去料对账：关曲面道 +1.3% / 开曲面道 −0.4% → 两个口径在"去了多少料"上吻合。差异全在分布：similarity 现在也报"切多 / 没切到"体素数（开曲面道 8135 / 418）。设计场零点系统性外偏 +0.030 mm（49318 个网格点量的）——"切到设计面"在体素口径里本来就显示成薄薄一层切多。结论一度写成"h=0.6 下 IoU/F1 对切到位有系统性惩罚"，但被 §48 推翻：去掉侧向工序后 F1/IoU 反而比基线更好——是刀在啃，不是指标在罚。教训：指标变差先怀疑刀路（§47.1）
点铣的代价 ✅ 退刀改 G0、进刀只留最后 1 mm 进给（前面 17 mm 快移）、链按"离上一条终点最近"重排（可整条反向）。叶轮 1 切长 55 → 12.3 m、叶轮 2 33.6 → 8.4 m、桌腿件 5.6 → 1.2 m，合格率一位不差。报告行现在带 切 / 空移 / 链间擦料，切长只算真切削
链间快移擦料 ✅ link_ok 按 0.5 mm 步距扫快移轨迹（刀尖 + 刃部圆柱）——仿真里 G0 不计切削，撞了也看不见。叶轮 1 原本 46/1225（3.8%） 条会擦到工件；链排序先取最近三条、优先选不擦料的 → 12（1.0%）。剩下的留给后处理（真实 CAM 也在这里报碰撞）
歪刀轴（五轴曲面道） ✅ axis_candidates：纯法向 → 24°/40° 锥面 × 8 方位，每个候选过 A 行程；同圈按"与上一点最像"排序保证连续；串链 >45° 不连。歪轴不改变切出来的形状（tip = p + R(n−a) 补偿），只改变刀杆去哪——叶轮 1 68%、叶轮 2 71% 的通过点是靠它进来的。叶轮 1 78.8 → 98.2%、叶轮 2 47.3 → 98.0%，过切 1.5% / 0.4%。倾角才是最后一根杠杆：40° → 91.2%、60° → 98.2%、75° → 98.1%。--surface-tilt 可调（默认 60°）。见 §45/§47
五轴曲面法向点铣 ✅ cam::surface：不经过高度场，球心放在 p + R·n、刀轴沿 n，球在设计面 p 相切。核心恒等式 tip = p + R(n − a) —— 刀轴 a 是自由的，法向超出 A 行程就把轴拉到 110° 极限、刀尖偏 R(n−a)，球照样相切（叶轮 1 的 45% 残料点原本栽在 A 超程，改后 0）。三道闸门：球面 R−0.03 / 刃部圆柱 R−0.03 / 刀杆 R+0.3；串链每段都过 sweep_ok（不许穿墙），法向差 >60° 不连。桌腿件 91.6 → 93.9%、不可达面 57.9 → 73.5%，过切不变；叶轮 1 61.7 → 78.8%、残料 37.0 → 19.8%。默认 --surface-d = min(精刀, Ø1.0)，--no-surface 关。见 §44
能力边界（叶轮实测，定轴链路） ✅ 两个真叶轮（Ø100×40 / 5.1 万面、Ø80×41 / 15.5 万面）只用定轴/3+2 时：解析合格 61.7% / 47.3%，过切只 1.3% / 0.3%（失败模式是"留料"不是"切坏"）。第二个件可达 86.3% 但可达面只 15.4% 合格——HeightMap 每列只认最上面那层。加上五轴曲面道后叶轮 1 到 78.8%（§44）；剩下的是刀杆塞不进通道（73% 的残料点）与五轴开粗，见 docs/项目记忆.md §40/§44
形状保真度度量 ✅ 三层口径：① 单向几何量（Δz / Δr）② 整实体体积（compare_with_design，过切/残料体积 + 定位回 G 代码行）③ 名义曲面逐点（surface_dev，正=过切深度、负=残料厚度）；口径与盲区见 docs/项目记忆.md §27
悬浮碎屑 ✅ RunConfig::drop_chips：跑完做一次 6 邻域连通块标记，只留最大块——切下来还"挂"在场里的碎块按掉落的切屑处理。体素 CSG 只做去除、不管连通性，不清理的话预览上会浮着一层小方块（花瓶实测丢掉 67 万格）

6. 下一步（按价值排序）

外部调研的价值点已提炼成 docs/工艺层补强-采纳清单.md（来源 docs/rust-cnc-cam-research.md， 25 章）。核心判断：调研的算法层可当规格用，但它对"仿真精度"只给了加体素一条路 （0.05 mm = 550 MB~2.7 GB），而我们的解析口径是第三条更便宜的路——守住，别被带跑。 真正补短板的是工艺层：链接安全 → 进给自适应 → 方向投票 → 侧铣判定 → 桶刀。 不采纳：真自适应 ADF（与确定性冲突）、全局 0.05 mm 体素、swarf 刀路、颤振 SLD。

-1. 链接安全（两级安全高度 + 三段折线） ⭐ 最急。link_ok 现在只计数擦料 （叶轮 1 有 8~12 处），不解决；每条链收尾 G0 抬 18 mm 再横移，66 m 空移里 50 m 是这个。 做法：skim_z(a,b) 沿 A→B 采样取"能过的最小高度"，order_runs 改成按 (是否安全, 抬刀高度) 排序，安全高度取 min(skim+余量, clear)。验收：擦料 ≤2、空移 <50 m、合格率不降。

  1. ~~五轴曲面法向点铣 + 歪刀轴（60°）~~ ✅ 做完了（§44/§45/§47）：叶轮 1 61.7% → 98.2%、叶轮 2 47.3% → 98.0%，过切 1.5% / 0.4%， 残料 0.2% / 1.6%。 侧刃铣没做（要先把网格拟合成直纹面，对非直纹叶片无解）。 点铣的代价已经压过一轮（§46）：叶轮 1 切长 55 → 12.3 m、叶轮 2 33.6 → 8.4 m。 沿曲面流线走刀做完了，没有收益（§50）：链 −3% / 空移 −3.8%，但切长 +2%、 块 +311——链的形状不是成本主体（64 m 空移里 50 m 是进退刀）， follow_flow 默认 false、--flow 留作实验。 通过率已经提上去了（§51）：neck_mm 四段模型 + 9 mm 避空颈把 Ø6 柄挡在 通道外，叶轮 1 到 98.0% / 残料 0.4%，刀杆撞 7516 → 1177。
  2. ~~凹角清根~~ ✅ 做完了（§41.2）：91.6% → 93.7%，过切不变，切长 +29%。 再往上被"刀径 vs 公差"卡住：90° 凹角要落进 ±0.15 得 R ≤ 0.36，再小断刀。
  3. 二次装夹（翻面）：桌腿件 13.6% 的面积在单次装夹下几何不可达 （背面 1732 mm² + 遮挡 328 mm²）。解析口径下这块折合约 17% 的残料面积， 是剩下最大的一块。做法已经清楚：绕 X 轴 180° 的位姿是精确的体素索引 置换（(i,j,k) → (i, ny−1−j, nz−1−k)，因为旋转中心取格心）， 设计网格与 cut_segs 用同一个 Frame 变换即可；缺的是把两套工序的 cut_segs 拼起来算解析口径、以及毛坯在第二次装夹时的"已切状态"传递。
  4. 残料重切（小刀）：新覆盖的 1177 mm² 里大部分仍是残料，Ø3 球头放不进去。 需要"仿真后读残料 → 聚类 → 换 Ø1.5 补一道"，即真正的一轮闭环。 （与 #0 是同一件事，合并做。）
  5. 剖切平面进 Bevy——HTML 预览版已有（HUD 滑块 + discard），窗口里还没接。五轴件的内腔不剖开根本看不见。
  6. 点选面 → 反查 creator（ADR-005 §交互）。溯源数据已经有了，缺的是拾取 + 图例面板。
  7. TileCache 增量上传进窗口（render 侧 11× 已实测，差 Bevy 那一步）。
  8. SimJob 进度条（事件层已备，面板接一下）。
  9. 自适应 LOD / k=2 按 level-1 分块 / 块索引第一遍并行 / G95 时间口径。
  10. 小刀切削成本：R0.5 锥度球头逐刀 3.4 ms（φ6 只要 0.24 ms）——小刀的 AABB 小但 sd_profile 的固定成本占比高，值得给"球头/锥度"加一条解析快路径。
  11. 大毛坯显式降粒度：默认 creator_sub = 8 换精度，R15 半球实测 49 MB； 只关心几何时调回 1/2/4，或 set_creator(0) 关闭溯源。

8. 已知环境坑

  • cargo test 打印大量 error deleting lock file——Windows 增量编译锁残留，无害，不是代码警告。
  • Bevy 0.20：shadows_enabled → shadow_maps_enabled；DefaultPlugins 已含 picking（重复加 panic）；Mesh 属性是带类型数组（传扁平 Vec<f32> 编译过、运行时 panic）；自定义着色器必须 WESL。
  • egui 自带字体无 CJK 字形（中文全方框）→ 已嵌 MiSans（assets/fonts/）。
  • Rust 2024：隐式借用模式里不能写 &v；unsafe fn 内每个不安全调用要显式包 unsafe {}。
  • rayon 只能经 voxel::par::pool()——绕过它直接调 par_iter 会另建全局池（实测 50 线程抢 24 核）。
  • 并行不是默认更快：blit_leaves_parallel 在逐刀（256 KB）上比串行慢 8.4 倍，已加 1 MB 门槛。加并行前先算"每块工作 vs fork-join 唤醒（15–50 µs）"。
  • 性能诊断不要用每刀 eprintln!——打印比被测对象贵，测出来的分布全偏。用 CNCSIM_PROF=1 + prof_take() / prof_take_write() / prof_take_box()（原子累加，跑完一次读）。
  • 建场和切削要分开计时：PROF_BOX 是建场（一次性），PROF_EVAL/WRITE 是切削（每刀）。混在一起看不出谁贵。
  • "数学上等价"的浮点改写要实测：cur * k_dist < x 与 cur < ceil(x * k_value) 在实数上等价、浮点下不等价（见 cut.rs::int_threshold_tests 的反向测试）。
  • uniform_value 适合大块（早退），count_ne 必须小块（要数清楚）。把后者也提到 32 会让铣光慢 8 ms。
  • 单位陷阱（最高频的一类 bug）：RunConfig.stock_size 是体素不是 mm；kin 旋转轴是度不是弧度；D 是寄存器号不是半径；DVec3 没有 / f64。完整 11 条见 docs/项目记忆.md §16。
  • 本机 cargo 走 rsproxy-sparse 镜像。
